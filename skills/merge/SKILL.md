# /wtflow:merge — 기본 브랜치 최신본을 작업 브랜치로

**사용자에게 내는 응답·질문·안내의 언어는 `${CLAUDE_PLUGIN_ROOT}/references/response-language.md`(요청마다 정하는 응답 언어)를 따른다 — 시작 전에 읽는다.**

**시작 전에 `${CLAUDE_PLUGIN_ROOT}/references/worktree-discipline.md`(브랜치 이름 규칙·Step 모델·note 종류)를 읽는다. `--close` 를 받았을 때만 `${CLAUDE_PLUGIN_ROOT}/references/host-adapter.md`(이슈 호스트 판별·CLI 대응)와 `body-rewrite.md`(체크박스 한 줄 켜기의 훅 계약)도 읽는다.**

작업이 길어지면 기본 브랜치가 앞서 나가 충돌이 쌓인다. 그걸 **MR 을 열기 전에** 작업 브랜치 쪽에서
해소해 둔다. `/wtflow:mr` 과 방향이 반대다:

| | 방향 | 무엇이 바뀌나 |
|---|---|---|
| `/wtflow:merge` | 기본 브랜치 → accumulator | **작업 브랜치만** 바뀐다 |
| `/wtflow:mr` | 현재 브랜치 → 기본 브랜치 (요청) | 기본 브랜치는 리뷰를 거쳐서만 바뀐다 |
| `/wtflow:merge --local` | accumulator → **로컬** 기본 브랜치 | 기본 브랜치가 리뷰 없이 바뀌고, 작업 브랜치·워크트리는 사라진다 (계약 8) |

**`/wtflow:mr` 이 MR 을 만들기 전에 이 스킬을 먼저 부른다**(`wtflow:mr` 계약 5). 그래서 보통은
따로 부를 일이 없다 — 직접 부르는 건 MR 과 무관하게 중간에 최신본을 당겨오고 싶을 때다.

⚠️ **머지 규칙은 이 문서에만 둔다.** 기준 브랜치 판정·메시지 형태·충돌 해소·검증은 전부 여기
계약이고, `wtflow:mr` 은 부르기만 한다. 양쪽에 적으면 한쪽만 고쳐져 어긋난다.

⚠️ **이 스킬은 기본 브랜치를 건드리지 않는다 — `--local` 을 받았을 때만 빼고.** 로컬에서 기본
브랜치에 작업 브랜치를 머지해 push 하면 리뷰를 건너뛴다 — 옵션 없이는 그 길을 쓰지 않는다.
`--local` 은 MR 없이 끝내기로 사용자가 정한 작업에만 쓰고, 그때도 push 는 하지 않는다(계약 5).

## 호출

`/wtflow:merge [-b <기본브랜치>]` · `/wtflow:merge --local [--close]`

| 인자 | 뜻 |
|---|---|
| 생략 | `develop`, 없으면 `main` 을 accumulator 로 가져온다 (원격을 fetch 해 맞춘 뒤 로컬 브랜치를 머지) |
| `-b <기본브랜치>` | 가져올 브랜치 명시 |
| `--local` | 방향을 뒤집는다 — accumulator 를 **로컬** `develop`(없으면 `main`)에 머지하고, 성공하면 워크트리·accumulator·mirror·스쿼시 브랜치를 지운다 (계약 8) |
| `--local --close` | 위에 더해, 머지가 들어갔으면 끝난 작업 항목을 켜고 다 켜지면 그 이슈를 닫는다 (계약 9). `--local` 없이 오면 무시하고 그 사실을 알린다 |

## 계약

1. **대상은 accumulator 다 — mirror 위에서 부르면 그 accumulator 워크트리로 세션을 옮긴다.**
   머지 커밋이 Step 에 섞이면 안 되는 것은 그대로고, 옮겨 갈 자리가 mirror 이름에서 바로 나오므로
   멈추는 대신 옮긴다.

   | 현재 브랜치 | 처리 |
   |---|---|
   | accumulator(`<prefix>/#<N>-<slug>` · `<prefix>/+<slug>`) | 그 자리에서 머지한다 — 아무것도 옮기지 않는다 |
   | mirror(`-<NNN>`) | accumulator 워크트리로 세션을 옮긴 뒤 머지한다 (아래 절차) |
   | 기본 브랜치 · detached | 보고하고 멈춘다 |

   **mirror 에서 옮겨 가는 절차** — 네 단계이고, 중간에 실패하면 멈춘다:

   1. **accumulator 이름을 뗀다** — mirror 이름 끝의 `-<NNN>` **하나만** 잘라낸다.
      `feat/#70-brush-smallmask-rle-format-004` → `feat/#70-brush-smallmask-rle-format`.
      ⚠️ slug 에도 숫자가 들어가므로 **끝의 `-[0-9][0-9][0-9]` 에만** 건다
   2. **워크트리를 찾는다** — `git worktree list --porcelain` 에서 그 브랜치가 체크아웃된 경로.
      `git branch --list` 의 `+` 마커로 판정하지 않는다 — 어느 경로인지를 알려주지 않는다
   3. **없으면 붙인다** — 브랜치는 살아 있는데 워크트리만 없는 상태는 정상 경로다
      (`wtflow-clean -w` 가 워크트리만 걷어낸 뒤). accumulator 이름으로 경로를 만들어 붙인다:
      ```
      git worktree add '.claude/worktrees/<N>-<slug>' '<accumulator>'
      ```
      - **`-b` 를 쓰지 않는다** — 있는 브랜치를 붙이는 것이지 새로 만드는 게 아니다
      - 경로는 accumulator 에서 prefix 와 `#` 를 뗀 것(`<N>-<slug>`, adhoc 은 `<slug>`) —
        `worktree-discipline.md` 의 `## 브랜치 이름 규칙` 그대로라 `plan` 이 만든 자리와 같다
      - **accumulator 브랜치 자체가 없으면 여기서 멈춘다** — 붙일 base 가 없다
   4. **진입한다** — `EnterWorktree({ path })`. `cd` 로 대신하지 않는다

   - **워킹트리가 더러운지는 옮겨간 뒤에 본다.** 지금 자리가 아니라 머지가 실제로 일어나는
     워크트리가 대상이다
   - **mirror 는 안 건드린다.** 머지 커밋은 accumulator 에만 쌓이고 mirror tip 은 그대로다
     — 계약 6 과 같은 이유다
2. **원격을 먼저 받아오고, 로컬 기본 브랜치를 머지한다.**
   ```
   git fetch origin <기본브랜치>                 # origin/<기본브랜치> 만 갱신된다
   git merge --no-ff '<기본브랜치>'              # 로컬 브랜치를 머지 → 'Merge branch ...' 형태
   ```
   - **기본 브랜치를 체크아웃하지 않는다** — 현재 워크트리 안에서 끝난다
   - **메시지를 손대지 않는다.** git 기본값 `Merge branch '<기본브랜치>' into <현재 브랜치>` 가
     그대로 이력이 된다. 현재 브랜치는 accumulator 이므로 이름에 Step 이 섞이지 않는다

   **로컬과 원격이 어긋나 있으면 머지하기 전에 맞춘다** — `git fetch` 는 `origin/<기본브랜치>` 만
   갱신하지 로컬 `<기본브랜치>` 는 건드리지 않는다. 그래서 둘의 관계를 먼저 본다
   (`git rev-list --left-right --count 'origin/<기본브랜치>...<기본브랜치>'`):

   | 관계 | 처리 |
   |---|---|
   | 같음 | 그대로 로컬을 머지한다 |
   | **로컬만 뒤처짐** | `git fetch origin <기본브랜치>:<기본브랜치>` 로 FF 갱신 후 머지 |
   | 그 외(로컬이 앞서거나 갈라짐) | **계약 7 로 간다 — 묻는다** |

   - ⚠️ **FF 갱신이 거부될 수 있다.** 그 브랜치가 다른 워킹트리에 체크아웃돼 있으면 git 이
     `refusing to fetch into branch ... checked out at ...` 로 막는다. 그때는 **`origin/<기본브랜치>`
     를 대신 머지하고, 메시지가 `Merge remote-tracking branch ...` 형태로 남는 이유를 보고에 적는다.**
     `update-ref` 로 우회하지 않는다 — 그 워킹트리의 인덱스가 ref 와 어긋나 없던 변경이 생긴다
   - **결과물은 어느 쪽이든 같다** — tree 와 흡수한 커밋이 동일하고 메시지 문자열만 다르다.
     로컬 형태를 기본으로 두는 건 일반적인 협업 이력과 형태를 맞추기 위해서다
3. **`--no-ff` 고정.** 머지 커밋이 남아야 언제 최신본을 흡수했는지 이력에 보인다
4. **충돌 해소 후 빌드로 검증한다.** 해소가 끝이 아니다:
   컴파일 언어 → `compileJava`/`compileTestJava` 등, TS → `npx tsc --noEmit`, Python → 구문 파싱.
   깨지면 커밋하지 않고 보고한다
5. **push 하지 않는다.** origin 반영·MR 은 `/wtflow:mr` 몫이다
6. **mirror 를 건드리지 않는다.** 이 머지 커밋은 accumulator 에만 쌓인다 — Step 에 속한 작업이 아니므로
   mirror 를 새로 만들지 않는다. 다만 accumulator tip 이 앞서므로, 다음 `/wtflow:commit` 이
   최상단 mirror 를 FF 로 끌어올린다

7. **기준이 갈리면 조용히 고르지 않고 묻는다.** 계약 2 의 관계 판정이 "그 외"(로컬이 앞서거나
   갈라짐)로 떨어지면 **머지 전에 멈추고 `AskUserQuestion` 으로 확인한다.**

   **왜 물어야 하나 — 어느 쪽을 고르냐로 결과가 통째로 달라진다.** 실제로 로컬이 원격보다
   19커밋 앞선 상태에서, 원격 기준으로는 `Already up to date.`(아무 일도 없음)이고 로컬
   기준으로는 19커밋을 흡수했다. 둘 다 정상 종료라 **틀린 쪽을 골라도 티가 나지 않는다.**

   질문에 **반드시 숫자를 함께 낸다** — 어느 쪽이 몇 커밋 앞서는지 없으면 고를 수가 없다:

   | 보기 | 언제 맞나 |
   |---|---|
   | 로컬 `<기본브랜치>` 기준 | 아직 push 안 한 머지가 로컬에만 있다 (다른 작업을 먼저 흡수한 경우) |
   | `origin/<기본브랜치>` 기준 | 로컬 브랜치가 실험·실수로 앞서 있어 버릴 것이다 |
   | 멈춤 | 왜 갈렸는지 모르겠다 — 사람이 먼저 확인한다 |

   - **`(추천)` 을 붙이지 않는다.** 어느 쪽이 맞는지는 사용자만 아는 로컬 사정이고, 추천을 달면
     그 사정을 확인하지 않고 통과시키게 된다
   - `wtflow:mr` 이 이 스킬을 부른 경우에도 **똑같이 멈추고 묻는다.** MR 을 만드는 흐름이라고
     해서 임의로 고르면, 잘못 고른 기준이 그대로 리뷰에 올라간다
   - 로컬이 **뒤처지기만** 한 경우는 묻지 않는다 — 계약 2 대로 FF 로 맞추면 그만이라 고를 게 없다

8. **`--local` 이면 accumulator 를 로컬 기본 브랜치에 머지하고 그 작업을 정리한다.**
   MR 을 올리지 않고 로컬 develop 에 바로 합치는 작업을 위한 것이다. 머지·삭제는 `wtflow-clean -M`
   이 하고, 이 스킬은 부르는 순서와 보고만 맡는다:
   ```
   git rev-parse --abbrev-ref HEAD                  # accumulator 이름
   git rev-parse HEAD                               # 작업 tip — 머지 판정에 쓴다
   git branch --list '<accumulator>-[0-9][0-9][0-9]'   # --close 면 — 커밋된 Step (스크립트가 지우기 전에)
   ExitWorktree({ action: "keep" })
   ${CLAUDE_PLUGIN_ROOT}/scripts/wtflow-clean '<accumulator>' -M -y
   ```

   | 계약 | `--local` 에서 |
   |---|---|
   | 1 대상은 accumulator | **그대로** — mirror 위면 accumulator 워크트리로 옮긴 뒤 이름을 읽는다 |
   | 2·3·4 develop 을 받아 머지·검증 | **먼저 하지 않는다** — 작업 브랜치를 그대로 합친다. 충돌이 났을 때만 돈다(아래) |
   | 5 push 안 함 | **그대로** — 로컬 develop 만 바뀐다 |
   | 6 mirror 안 건드림 | **해당 없음** — 머지가 성공하면 mirror 도 지운다 |
   | 7 로컬·원격 기준 질문 | **묻지 않는다** — 합치는 대상이 로컬 develop 하나라 고를 기준이 없다. fetch 도 하지 않는다 |

   - **develop 을 먼저 받지 않는 이유** — 머지 커밋을 작업당 하나로 둔다. 충돌이 날 때만
     develop 을 받아 푼 뒤 다시 합친다(아래 「충돌로 멈췄을 때」) — 그때만 머지 커밋이 둘이 된다
   - **워킹트리가 더러우면 나가기 전에 멈춘다** — 중단 트리거와 같다. 지울 워크트리에 남은 변경을
     스크립트가 보류로 처리하면 머지만 되고 정리는 반쯤 남는다
   - **나가는 순서와 `action: "keep"`, 출력을 원문으로 옮기는 것은 `wtflow:clean` 의 계약 1·3 그대로다.**
     `wtflow:clean` 을 `Skill()` 로 부르지 않는다 — 모델 호출이 막혀 있다. 스크립트를 직접 부른다
   - **`-f` 를 붙이지 않는다** — 머지가 성공하면 스크립트가 미보존 브랜치까지 지운다. 남는 것은
     더러운 워크트리뿐이고, 그건 버리지 않고 보고할 대상이다
   - `-b` 와 함께 오면 멈추고 알린다 — 스크립트가 `develop`(없으면 `main`)으로 고정한다

   **결과는 종료 코드가 아니라 tip 이 들어갔는지로 판정한다.** 머지 뒤 워크트리 제거가 보류돼도
   종료 코드는 1 이다:
   ```
   git merge-base --is-ancestor '<작업 tip>' '<기본브랜치>'
   ```

   | 판정 | 처리 |
   |---|---|
   | tip 이 들어감 + 종료 코드 0 | 머지·정리 완료 |
   | tip 이 들어감 + 종료 코드 1 | **머지는 됐다.** 정리가 일부 남았다 — 스크립트가 보류한 줄(워크트리 변경 등)을 그대로 전한다 |
   | tip 이 안 들어감 | **아무것도 안 지워졌다** — 그 워크트리로 다시 `EnterWorktree({ path })` 한다. 머지 충돌이면 아래 「충돌로 멈췄으면」 으로 이어 가고, 기본 브랜치 워크트리가 더러우면 사유를 보고하고 멈춘다 |

   - **기본 브랜치가 어디에도 체크아웃돼 있지 않아도 멈추지 않는다** — 스크립트가 저장소 밖에 임시
     워크트리를 만들어 머지하고 지운다. 메인 체크아웃을 기본 브랜치로 바꾸라고 안내하지 않는다
   - **충돌로 멈췄으면 사용자에게 넘기지 않고 이어서 한다** — 스크립트 출력에 `✗ 머지 실패(충돌 등)`
     가 있을 때다. 기본 브랜치 워크트리가 더러워 멈춘 것(`--merge:` 로 시작하는
     중단 줄)은 해당하지 않는다 — 그건 보고하고 멈춘다
     1. 그 워크트리로 `EnterWorktree({ path })` 한다
     2. **계약 2~4 를 옵션 없이 돈다** — 로컬 develop 을 accumulator 로 머지하고, 충돌을 풀고, 빌드로
        검증해 커밋한다. **계약 7 은 묻지 않고 로컬 develop 을 머지한다** — 합칠 대상이 로컬 develop
        이라 받아오는 쪽도 같아야 한다. fetch 도 하지 않는다
     3. 계약 8 을 처음부터 **한 번만** 다시 돈다 — 2 에서 develop 을 흡수했으므로 충돌 없이 합쳐진다.
        2 의 머지 커밋은 accumulator 에만 있지만 스크립트가 mirror 보다 앞선 accumulator 를 합치므로
        mirror 를 손으로 맞추지 않는다. 또 충돌하면 그 사이 develop 이 움직인 것이라 보고하고 멈춘다
     - 2 에서 중단 트리거(제품 결정이 필요한 충돌·빌드 실패)에 걸리면 거기서 멈춘다 — 평소의 merge 와 같다
   - **`wtflow:mr` 이 이 스킬을 부를 때는 `--local` 이 붙지 않는다** — 리뷰를 받으려는 흐름이다

9. **`--local --close` 면 머지가 들어간 뒤 끝난 작업 항목을 켜고, 다 켜지면 그 이슈를 닫는다.**
   명령은 `host-adapter.md` 의 `## 이슈 명령 대응` 에서 `이슈 본문 조회`·`이슈 닫기` 행을 꺼낸다.
   이슈 번호는 계약 8 에서 읽은 accumulator 이름의 `/#` 뒤 정수다 — 워크트리를 나간 뒤에는
   그 이름을 다시 읽을 곳이 없다.

   | 상황 | 처리 |
   |---|---|
   | 계약 8 판정이 「tip 이 안 들어감」 | **켜지도 닫지도 않는다** — 합쳐지지 않은 작업이다 |
   | 「tip 이 들어감」 (종료 코드 0 이든 1 이든) | 아래 순서로 켠 뒤 닫는다. 정리가 일부 남은 것은 이슈와 무관하다 |
   | accumulator 가 `/+<slug>` (이슈 없는 작업) | 닫을 이슈가 없다고 한 줄 알리고 끝낸다 — 머지·정리는 이미 그대로 됐다 |

   **순서 — 켜고, 다시 읽고, 닫는다:**
   1. **이슈 본문을 읽고 `작업 항목` 의 `- [ ]` 줄을 모은다**
   2. **줄마다 끝났는지 본다 — 근거는 둘뿐이다.** 테스트·명령을 돌려 확인하지 않는다
      - **git log** : 그 항목의 Step 커밋이 기본 브랜치에 들어갔다 — 계약 8 에서 읽은 mirror
        `-<NNN>` 의 번호, 또는 `git log '<기본브랜치>'` 에서 그 항목을 구현한 커밋
      - **세션 맥락** : 이 세션에서 그 항목을 구현해 커밋한 기록
   3. **끝난 줄만 켠다** — `wtflow:commit` 의 체크박스 동기화와 같은 경로다. 호출마다 `- [ ]` 한 줄만
      `- [x]` 로 바꾸고, 앞에 `WTFLOW_CHECKBOX_SYNC=1` 을 붙인다(`body-rewrite.md`).
      근거를 못 찾은 줄은 **추측해서 켜지 않는다**
   4. **`작업 항목` 이 전부 `- [x]` 면 닫는다.** 하나라도 남으면 닫지 않고 그 줄과 근거를 못 찾았다는
      사실을 알린다
   - **완료 조건은 닫기 판정에 쓰지 않는다** — 켜지도 않고, 남아 있어도 닫는다. 조건을 확인하는 자리는
     `wtflow:commit` 이 마지막 작업 항목을 닫는 커밋이다
   - **닫기만 한다** — 댓글·라벨·마일스톤을 건드리지 않는다
   - 닫기 실패는 머지·정리를 되돌리지 않는다 — 실패 사유와 수동으로 닫을 명령을 보고한다
   - **모델이 스스로 `--close` 를 붙이지 않는다** — 저장소에 따라 이슈를 사람이 직접 닫는 정책이 있다

## 충돌 해소 감각

- **import·목 선언 충돌은 대개 "양쪽 다 필요"** 다. 한쪽을 버리기 전에 그 심볼이 정말 안 쓰이는지 본다.
- **한쪽이 다른 쪽의 구형을 들고 오는 경우**가 있다(브랜치를 딴 시점이 달라서). 최신 정의를 살리고
  구형 중복을 버린다 — 어느 쪽이 최신인지는 `git log` 로 확인하고 추측하지 않는다.
- **같은 문제를 다르게 고친 두 브랜치**가 부딪히면 한쪽을 기계적으로 취하지 말고,
  **실제로 검증된 쪽을 기본으로 삼고 다른 쪽의 고유 기여만 흡수**한다. 그 판단 근거를 보고에 적는다.
- 테스트 파일 충돌은 런타임에 영향이 없더라도 **버리지 말고** 양쪽 케이스를 살린다.

## 중단 트리거

- 현재 브랜치가 기본 브랜치이거나 detached → 보고하고 멈춘다. **mirror 는 여기 안 든다** — 계약 1 대로 옮겨 간다
- mirror 에서 뗀 accumulator 브랜치가 없음 → 보고하고 멈춘다. 워크트리를 붙일 base 가 없다
- `git worktree add`·`EnterWorktree` 실패 → 보고하고 멈춘다. **원래 자리에서 대신 머지하지 않는다**
- 워킹트리가 더럽다 → 머지 전에 커밋하거나 치우게 하고 멈춘다(머지가 변경을 빨아들이면 안 된다).
  옮겨 간 경우 대상은 **옮겨간 워크트리**다
- 충돌 해소에 **제품 결정**이 필요(둘 중 어느 설계를 남길지) → 선택지 제시 후 대기
- 로컬 기본 브랜치와 원격이 갈림(로컬이 앞서거나 갈라짐) → **머지 전에** 계약 7 로 묻고 대기
- 빌드·타입 검사 실패 → 커밋하지 않고 보고
- fetch 실패(원격 접근 불가) → 보고하고 멈춘다. **낡았을 수 있는 로컬 기본 브랜치를 그대로 머지하지 않는다** — 원격을 못 봤으면 뒤처졌는지 알 수 없다
- `--local` 인데 `ExitWorktree` 실패 → 스크립트를 부르지 않고 멈춘다. 셸이 사라진 디렉토리에 남는다
- `--local` 인데 tip 이 기본 브랜치에 안 들어감 → 계약 8 의 판정 표대로 워크트리로 돌아온다. 충돌이면 develop 을 받아 풀고 **한 번만** 다시 합치고, 그 밖의 사유는 보고하고 멈춘다. **`-f` 를 붙여 다시 부르지 않는다**

## 보고 형식

머지 커밋 해시·메시지 / 충돌 파일과 **어떻게 해소했는지** / 빌드 검증 결과 / push 안 됨 명시 /
다음 단계(`/wtflow:mr`).

**다음 단계는 `${CLAUDE_PLUGIN_ROOT}/references/next-steps.md` 의 블록을 낸다** — 정리 옵션까지 함께.
`--close` 줄을 빼는 경우도 그 문서가 갖는다.

`wtflow:mr` 이 이 스킬을 부른 경우에는 이 블록을 내지 않는다 — 이미 그 명령 안이다.

**mirror 에서 옮겨 왔으면 맨 앞에 한 줄 더한다** — 어느 브랜치에서 어느 워크트리로 갔는지.
워크트리를 새로 붙였으면 그 사실도 같이 적는다. 안 적으면 머지 커밋이 어디 쌓였는지 모른다.

```
세션 이동: feat/#70-…-004 → .claude/worktrees/70-brush-smallmask-rle-format (워크트리 새로 붙임)
```

**`--local` 이면 보고가 다르다** — 스크립트 출력 원문 / 계약 8 의 판정 결과 한 줄 / push 안 됨 명시 /
`--close` 면 켠 작업 항목과 그 근거(커밋 hash) / 닫은 이슈 번호, 또는 남은 줄과 닫지 않은 이유(계약 9).
위 다음 단계 블록은 내지 않는다 — MR 로 갈 작업이 아니다. 충돌을 풀고 다시 합쳤으면 그 머지 커밋과
충돌 해소 내용을 함께 적는다.
