# /wtflow:auto — 워크트리 작업 항목 자율 순회

**시작 전에 `${CLAUDE_PLUGIN_ROOT}/references/worktree-discipline.md`(브랜치 이름 규칙·K 모델·note 계층)와 `${CLAUDE_PLUGIN_ROOT}/references/learning-protocol.md`(사전문답 — `--no-ask` 가 없으면 순회 중에도 낸다)를 읽는다. 커밋 메시지 형식은 `${CLAUDE_PLUGIN_ROOT}/references/convention-precedence.md`(어디에 적힌 컨벤션이 이기는지) 를 먼저 읽고 `commit-convention.md` 를 읽는다.**

`/wtflow:plan` 이 만든 plan 의 작업 항목(K)들을 **사람이 K마다 끼어들지 않아도** 끝까지 돌린다.
각 K = 구현 → 가벼운 검증 → `/wtflow:commit` 로컬 커밋. **commit 메커니즘은 직접 짜지 않고 `/wtflow:commit` 에 위임**한다(분기·테스트·누적 contract 단일화).

## 왜 스킬인가

자연어 "알아서 다 해줘"는 세션마다 해석이 흔들리고, 자동 push 는 회복이 어렵다.
이 스킬의 가치는 자동화 자체가 아니라 **자동화에 가드레일을 계약으로 고정**하는 것 —
로컬 커밋만, 한 작업 항목=한 K, 모호하면 멈춤. 그래서 "편함"과 K-모델의 "안전성"을 동시에 가져간다.

## 호출

`/wtflow:auto [작업 항목 범위] [--from <K>] [--only <K[,K,...]>] [--no-test] [--no-ask] [--push] [--dry-run]`

- 인자 없음(기본): 현재 세션 plan 의 **모든 작업 항목**을 K 오름차순으로 자율 순회
- `--from <K>`: K 부터 재개(이전 K 는 이미 커밋됐다고 간주) — 테스트 실패로 멈춘 뒤 고치고 이어갈 때
- `--only <K,...>`: 지정한 K 들만
- `--no-test`: 각 `/wtflow:commit` 에 `--no-test` 전달(빠른 반복 — 검증 책임은 사용자)
- `--no-ask`: 순회 중 사전문답을 끈다. `❓` 가 붙은 K 앞에서도 멈추지 않고, 내가 정하고 넘어간 설계 선택만 순회 뒤에 모아 낸다(기본은 멈추고 묻는다)
- `--push`: 각 K 커밋을 origin 에도 push(기본 OFF — 이 스킬의 기본은 **로컬만**). 명시 안 하면 절대 push 안 함
- `--dry-run`: 구현·커밋 없이 plan→K 매핑과 각 K 의 변경 대상만 출력하고 멈춤(계획 확인용)

plan 출처 우선순위: ① 같은 세션의 `/wtflow:plan` plan → ② 사용자가 인자/대화로 준 K 목록 → ③ **이슈 본문의 `작업 항목` 체크리스트**(항목 N = K N, 이슈 작업에만 있다).
plan 을 찾을 수 없으면 `/wtflow:plan <N>`(이슈가 없으면 `/wtflow:plan "<작업 설명>"`) 을 먼저 돌리라고 안내하고 멈춘다.
**이슈 없는 작업은 ③ 폴백이 없다** — 세션이 끊겼으면 plan 을 다시 돌려야 한다(mirror 분기는 이미 커밋된 K 만 알려주지 남은 항목을 알려주지 못한다).

> **작업 항목이 어디 사는지를 accumulator 이름이 정한다.** `/#` 뒤 정수 → 이슈 #N 본문의 체크리스트,
> `/+` 뒤 문자열 → **이 세션의 plan 출력**(파일 없음, 완료는 mirror 분기로 드러난다).
> **이 스킬은 이슈 유무를 가리지 않는다** — 순회·검증·정지 정책은 완전히 같고, 체크박스를 켤 데가
> 있는지만 갈리며 그 처리는 wtflow:commit 담당이다.

## 전제 (없으면 멈춤·보고)

1. **워크트리 안** — `git rev-parse --show-toplevel` + `git worktree list` 로 현재가 main 워킹트리가 아닌 워크트리인지 확인. 밖이면 멈춘다(이 스킬은 워크트리 전용).
2. **작업 트리 상태 인지** — 시작 시 `git status` 로 기존 uncommitted 변경 유무 파악. 있으면 첫 K 가 그걸 빨아들이지 않도록 사용자에게 보고 후 결정(별도 커밋할지/포함할지).
3. **plan 존재** — 위 출처 중 하나로 K 목록 확정.

## 계약 (보장되어야 하는 것)

1. **워크트리 브랜치 그대로** — 체크아웃·브랜치 이동 금지(새 브랜치 생성은 wtflow:commit 이 K 분기로 처리). origin push 는 `--push` 명시 시만.
2. **한 작업 항목 = 한 K** — K 번호는 **작업 항목 번호 = plan Step 번호**에 고정. 한 항목 안에 태스크가 여럿이면 **같은 `-K` 로 태스크마다 커밋을 누적**(한 항목을 커밋 없이 한 덩어리로 진행 금지 — 가장 흔한 실수).
3. **커밋은 /wtflow:commit 에 위임** — git add/commit/branch 를 직접 실행하지 않는다. K 단위로 `/wtflow:commit "<메시지>" -K <K>` 를 호출. 테스트 게이트·분기 누적(fast-forward)·amend 금지·로컬 한정·**체크박스 동기화**는 전부 그 스킬의 contract — 이 스킬은 시점만 지시(아래 7번).
4. **커밋 메시지는 `commit-convention.md` 의 `## Subject`** — 형식·언어를 여기 다시 적지 않는다. "코드가 뭘 했나"가 아니라 "동작·기능이 뭐가 달라졌나" 관점. 작업 항목 제목을 그대로 베끼지 말고 실제 변경에 맞춰 작성.
5. **K 사이 자율 진행** — 한 K 가 깨끗이 커밋되면 **다음 K 진행에 재허락을 묻지 않는다**(그게 이 스킬의 목적). 단, 멈춤 트리거(아래)에 걸리면 즉시 정지하고 보고.
6. **로컬 커밋만** — `--push` 없으면 어떤 단계에서도 push·MR·force 금지. 마지막 요약에서 "push 안 됨 — 다음 단계(테스트·MR)는 사용자 결정"을 명시.
7. **K 완료 신호 = `--done`** — K 를 닫는 마지막 커밋의 `/wtflow:commit` 에 `--done` 을 전달(동작·실패 처리는 wtflow:commit contract). push 여부와 무관하게 반영. 이슈 작업이면 체크박스가 켜지고, **이슈 없는 작업이면 무시된다**(켤 곳이 없다 — mirror 분기가 완료를 대신 드러낸다). 어느 쪽이든 **전달은 똑같이 한다** — 모드를 여기서 가리지 않는다.

## 루프 (각 작업 항목 K)

K 오름차순으로 반복:

1. **선언** — `### K{N}: <작업 항목 요약>` 한 줄과 이번에 손댈 파일/위치(plan 의 "관련 파일/위치") 출력. 사용자가 진행 상황을 따라올 수 있게.
2. **구현** — 해당 작업 항목을 구현(Edit/Write). 한 항목이 여러 태스크면 **태스크 경계에서 끊어** 3~4 를 반복(같은 K 로 누적 커밋). **다음이면 끊어 별도 커밋**:
   - **리팩터/이동 ↔ 동작 변경** — 섞으면 리뷰·revert 어려움 (리팩터 먼저 커밋, 그 위에 기능)
   - **독립적으로 검증·되돌리기 가능한 단위** — 각 커밋이 그 자체로 말이 되게
   - **서로 다른 관심사·모듈** — 무관한 변경을 한 커밋에 묶지 않기
   작은 K(단일 변경)는 굳이 쪼개지 말 것 — over-split 은 noise. 경계는 plan 의 태스크 힌트(있으면) 참고하되 **구현 중 판단이 우선**. 하위 커밋은 `Na`(1a·1b…)로 라벨해 진행 로그에만 남기고, **작업 항목·mirror 는 K 단위만** — `Na` 는 이슈 체크박스에도 mirror 분기 이름에도 절대 넣지 않는다(2a·2b 모두 `-K 2`, mirror `-002`).
3. **가벼운 검증** — 빠른 피드백용 최소 검사만. 변경 성격에 맞게:
   - 셸/스크립트 → `bash -n <file>`
   - TS/JS → `npx tsc --noEmit` 또는 `npm run lint`(해당 시)
   - Kotlin/Java 등 컴파일 언어 → 가능하면 빠른 컴파일(`./gradlew compileKotlin` 등)
   - 마땅한 빠른 검사가 없으면 생략하고 4 로(전체 회귀는 wtflow:commit 이 함)
   ⚠️ 전체 테스트를 여기서 다시 돌리지 않는다 — wtflow:commit 의 테스트 게이트와 중복.
4. **커밋 위임** — `/wtflow:commit "<type(scope): 요약>" -K {N}` 호출(`--no-test`/`--push` 는 인자 그대로 전달). **이 커밋이 K 의 마지막 태스크면 `--done` 추가**(K 단일 커밋이면 항상 `--done`) → 이슈 작업이면 항목 N 체크박스가 켜진다.
5. **결과 확인** — wtflow:commit 요약을 읽는다. 테스트 실패·non-FF·"주제 불확실" 등 이상 신호면 **멈춤 트리거**로 처리. 정상이면 commit hash·분기명·체크된 작업 항목을 진행 로그에 적고 다음 태스크/다음 K 로.
6. **항목 종료** — 작업 항목의 모든 태스크가 커밋되고 `--done` 을 넘겼으면 K 종료. 다음 K 로(재허락 안 물음).

**사전문답은 순회 중에도 낸다(기본).** plan 이 `❓` 를 붙인 K 는 **그 K 를 시작하기 전에** 멈추고
묻는다(`references/learning-protocol.md` `## 1. 예측 후 공개` · `## 4. 설계 선택은 두 안을 나란히` ·
`## 5. 변경 압력 예측`). 무중단이 이 스킬의 목적이지만, 판단이 든 자리까지 건너뛰면 순회가 끝났을 때
작업자가 쥔 게 없다. `❓` 가 없는 K 는 묻지 않고 그대로 지나간다.

- 한 K 의 문항은 **한 번의 `AskUserQuestion` 호출에 최대 3문항**으로 모은다(`## 사전문답은 전부
  AskUserQuestion 으로 낸다`). 설계 선택 보기에만 `(추천)`, 예측·변경 압력 보기에는 붙이지 않는다
- 답을 받으면 그 자리에서 채점하고 곧바로 구현으로 넘어간다. **"다음 K 로 갈까요?" 는 묻지 않는다**
  — 순회를 끝까지 도는 것은 이 스킬을 부른 시점에 이미 정해졌다

**`--no-ask` 면 순회 중에는 묻지 않는다.** `❓` K 라도 멈추지 않고, 임의로 정하고 넘어간 설계 선택을
근거와 함께 적어 뒀다가 마지막 브리핑 뒤에 **골랐어야 할 두 안 + 변경 압력 예측으로 모아 낸다**.
이 사후 모음도 산문이 아니라 `AskUserQuestion` 이고 한 번의 호출에 최대 3문항이다 — 안 멈춘 것이지
안 묻는 게 아니다.

전부 끝나면 **`/wtflow:briefing` 을 호출해 전체 작업 브리핑을 출력**한다(범위 = accumulator base..HEAD). 브리핑이 K별 커밋·변경 파일·검증·기술선택을 구조화해 정리하므로 별도 수기 요약은 생략. 브리핑 뒤에 **push 여부(기본 안 됨)**, 커밋된 K 목록(이슈 작업이면 체크된 항목도), 사용자가 할 다음 단계(통합 테스트·MR), 동기화 못 한 항목 수동 체크 안내를 덧붙인다. (wtflow:briefing 이 범위 추정 실패 등으로 못 돌면 막지 말고 인라인 요약으로 폴백)

## 결정·중단 트리거 (걸리면 즉시 정지 + 보고, 임의 진행 금지)

- **검증/테스트 실패** — 가벼운 검증 실패 또는 wtflow:commit 테스트 게이트 실패. 그 K 에서 멈추고 원인 보고(고친 뒤 `--from <K>` 로 재개).
- **작업 항목 모호** — plan 의 항목이 구현 방향을 특정하기에 불충분. 추측 구현 대신 질문.
- **아키텍처 트레이드오프** — 선택지 비교만 제시하고 결정 대기.
- **스코프 확장** — 작업 항목 밖으로 번지면 진행 전 보고.
- **파괴적·외부 동작** — force-push, 다른 브랜치 reset, amend/rebase, 운영 영향, 외부 서비스 전송 등은 명시 동의 전 금지.
- **non-FF / drift** — wtflow:commit 이 같은 K 분기 tip 이 HEAD 조상이 아니라고 보고하면 멈춤.
- **plan 불일치** — 현재 브랜치가 작업 식별자(이슈번호·slug)와 안 맞거나 plan K 와 실제 작업이 어긋나면 보고.

멈출 때는 **어디까지 커밋됐고(어느 K), 무엇 때문에 멈췄고, 어떻게 재개하는지(`--from`)** 를 명확히 적는다.

질문·선택지를 사용자에게 띄울 땐(작업 항목 모호·아키텍처 트레이드오프 등) 산문 말고 `AskUserQuestion` 으로 묻는다(보기 첫째에 추천안 `(추천)`). 자유 입력은 자동 "Other" 로 보장되니 "직접 입력" 보기는 넣지 않는다.

## 짧은 변형

- "알아서 끝까지" / "작업 항목 다 돌려" → 인자 없이 전체
- "K2부터 다시" / "고쳤으니 이어가" → `--from 2`
- "3번만" / "K3, K4만" → `--only 3` / `--only 3,4`
- "테스트 빼고 빨리" → `--no-test`
- "묻지 말고 쭉" / "문답 빼고" / "멈추지 말고" → `--no-ask`
- "푸쉬까지" / "origin 에도" → `--push`
- "계획만 보여줘" / "뭐 건드릴지만" → `--dry-run`

## 비고

- 이 스킬은 **사용자만 명시 호출**(frontmatter `disable-model-invocation: true`) — 자율 다중 커밋은 의도적으로 사람이 시작해야 한다.
- 단일 작업 항목 하나만 커밋할 거면 이 스킬 대신 `/wtflow:commit` 을 직접 부르는 게 맞다. wtflow:auto 는 **여러 K 를 연속**으로 돌릴 때의 도구.
- 커밋·분기·테스트·push 의 모든 세부는 `/wtflow:commit` 의 contract 를 따른다 — 이 스킬은 그 위의 순회·정지 정책만 더한다.
- 워크트리 브랜치는 origin 에 push 안 함. K 분기(`<accumulator>-<KKK>`)도 기본 로컬, `--push` 시에만 노출. 워크트리 브랜치를 올리는 것은 `/wtflow:mr` 만의 예외다 — 이 스킬은 `--push` 여도 올리지 않는다.
- plan 은 자주 틀린다 — 진행 중 자연어로 K 재조정 가능(그 시점부터 K 번호만 일관 유지).
