# /wtflow:briefing — 작업 브리핑 생성

**시작 전에 `${CLAUDE_PLUGIN_ROOT}/references/worktree-discipline.md`(브랜치 이름 규칙·K 모델·note 계층)와 `${CLAUDE_PLUGIN_ROOT}/references/host-adapter.md`(이슈 호스트 판별·CLI 대응)를 읽는다. `--mr` 이면 `${CLAUDE_PLUGIN_ROOT}/references/convention-precedence.md`(어디에 적힌 컨벤션이 우선하는지) 를 읽고 `pr-convention.md`(MR 제목·본문 형식)도 읽는다.**

## 호출

`/wtflow:briefing [<범위>] [-t <제목>] [--mr] [--no-table] [--detail] [--no-fence]`

- `<범위>` (선택): git revision 범위. 미지정 시 자동 추정
  - 워크트리면 `<accumulator base>..HEAD` (wtflow:commit accumulator 또는 `origin/develop`/`origin/main` merge-base)
  - 그 외 현재 브랜치의 `develop`/`main` 대비 범위
- `-t <제목>`: 문서 제목. 미지정 시 브랜치명/이슈에서 추론
- `--mr`: 전체 통합본 대신 **MR description 압축본** — 형식·상한은 `pr-convention.md` 를 따른다 (`### MR description 압축본`)
- `--no-table`: 기술 선택 표(7번) 생략
- `--detail`: 작업 항목을 커밋별 세부 체크리스트로 확장 (기본은 "무엇/왜" 한 줄 요약)
- `--no-fence`: 출력 전체를 감싸는 코드펜스를 제거하고 평범한 마크다운으로 출력 (기본은 전체 한 펜스 — 계약 6). 터미널 렌더로 정독하기 좋으나 복사 시 헤더·표 구조가 깨질 수 있음

## 계약 (보장되어야 하는 것)

1. **사실 수집 (날조 금지가 최우선)** — 다음 출처에서만 내용을 채운다:
   - `git log <범위> --pretty` : 커밋 = 작업항목(K). 커밋 해시·subject 그대로 사용
   - `git diff --stat <범위>` / `--name-only` : 영향 범위·파일·증감 통계
   - **대화 맥락** : 결정 사항, 고려했지만 안 쓴 대안과 그 이유, 검증 결과
   - 코드/문서(Read·Grep) : 잔존 참조 확인, 의존 전제
   - 추정·일반론으로 빈칸을 메우지 않는다. 근거가 없으면 2번 규칙을 따른다

2. **모르는 칸은 비우거나 묻는다** — 특히 "고려했지만 안 쓴 대안 / 그 이유"는 **실제 논의·검토된 것만** 적는다.
   - 대화/커밋에 근거가 없는 대안을 그럴듯하게 지어내지 말 것
   - 핵심 정보(왜 이 선택인지, 안 쓴 대안)가 비면 `(미상 — 확인 필요)` 로 표시하거나 사용자에게 한 번 묻는다

3. **작업 내용은 "무엇/왜"만 간결하게** — 기본은 커밋 1개 = **한 줄**("무엇을 했고 왜"). 코드가 어떻게 했는지·단계별 체크리스트는 적지 않는다(독자는 무엇/왜만 알면 됨). 세부가 필요하면 `--detail` 일 때만 커밋별 체크리스트로 확장. 커밋 해시는 참조용으로 끝에 첨부

4. **검증 섹션은 실제 실행한 것만** — 대화에서 실제로 돌린 검증(`tsc --noEmit`, `next lint`, 테스트)만 ✅로. 안 돌린 건 `[ ]`(예정)으로. 통과 안 한 걸 통과로 쓰지 않는다

5. **출력만 — 파일 수정·커밋 안 함** — 브리핑 텍스트만 출력(read-only). 사용자가 원하면 별도로 저장

6. **기본: 출력 전체를 한 코드펜스로 감싼다 (raw 복사 호환)** — 브리핑 출력 **전체**(제목·`##`/`###` 헤더·불릿·체크리스트·표 포함)를 **하나의 ` ```markdown ` 코드펜스**로 감싸서 낸다. 이유: 터미널이 마크다운을 렌더하면 복사 시 `##`·표·불릿 구조가 사라진 텍스트만 잡혀 MR·Notion 에서 깨진다. 전체를 펜스로 싸면 터미널이 **raw 마크다운 그대로** 보여줘, 통째로 긁어 붙이면 헤더·표·불릿이 전부 정상 렌더된다.
   - **표 raw 가독성**: 표는 컬럼을 공백 패딩하고 구분선(`---`)을 컬럼 폭에 맞춰 늘려 정돈된 표처럼 보이게 한다(`|--|` 최소 표기 금지). ※ CJK 문자는 더블폭이라 모노스페이스 완벽 정렬은 한계 — 적당히 패딩(렌더는 어차피 정상).
   - **내부에 별도 ``` 코드블록을 두지 않는다** — 전체가 한 펜스라 중첩되면 깨진다. 코드 예시가 꼭 필요하면 인라인(`` `...` ``)이나 들여쓰기로.
   - **`--no-fence`**: 이 펜스를 제거하고 평범한 마크다운으로 출력 → 터미널에서 렌더되어 정독·검토에 좋다(대신 복사 시 구조 깨질 수 있음). `--mr`·`--detail` 등과 자유 조합.

## 결정·중단 트리거

- git 범위 추정 실패 / 커밋 0개 → 사용자에게 범위 확인
- "안 쓴 대안·이유"의 근거가 대화에 없음 → 날조 대신 `(미상)` 표기 + 필요 시 1회 질문
- 작업이 진행 중(미완)이면 → 완료/미완을 체크박스로 구분, "선반영"·"후속" 명시
- 백엔드 등 외부 의존이 있으면 → "전제/의존" 섹션으로 분리 명시

## 출력 형식 (전체 통합본)

```
# [<scope>] <제목>

## 요약
<2~4문장: 무엇을 왜 어떤 방식으로. 모델/전략·범위·완료 상태>

## 1. 배경 및 문제 정의
<기존 상태 + pain point. 코드/대화 근거>

## 2. 목표
<달성 목표 불릿 + 비범위(Non-goals)>

## 3. 한 일 (무엇/왜)   ※ 기본: 한 줄씩. --detail 이면 커밋별 체크리스트로 확장
- **<무엇을 했나>** — <왜 (목적/효과)>  `<hash>`
- **<무엇을 했나>** — <왜>  `<hash>`
...
   (--detail: 위 각 항목을 `**K1 — <subject>** \`<hash>\`` + 하위 `[x]` 체크리스트로)

## 4. 영향 범위

## 5. 검증
- [x] 실제 실행한 검증
- [ ] 예정(외부 의존)

## 6. 전제 / 의존 (있을 때만)

## 7. 기술 선택 및 근거   ※ --no-table 이면 생략. 표는 패딩·구분선 확장으로 정돈(계약 6)
### 선택한 방법 & 이유

   (※ 실제 논의된 대안만. 근거 없으면 행을 만들지 않는다)

## 8. 결정 사항 요약 (TL;DR)
<번호 매긴 최종 결정 5~7개>

## 9. 오픈 이슈 / 비고
<후속·미해결·범위 밖으로 분리한 것>

### MR description 압축본 (`--mr`)

형식은 전부 `pr-convention.md` 가 갖는다 — 저장소 MR 템플릿 우선 규칙, 템플릿이 없을 때의 기본 템플릿,
셀 수 있는 상한, UI 가 이미 보여주는 것 금지, 덜어낸 근거를 어디로 가리키나.
**여기 사본을 두지 않는다** — 두 벌이 되면 한쪽만 고쳐져 갈린다.

⚠️ 상한은 **쓰고 나서 세어 본다.** 여기서 세지 않으면 형식을 검사하는 지점이 아예 없다.

## 짧은 변형

- "MR용으로" / "엠알" → `--mr`
- "표 빼고" → `--no-table`
- "develop 대비" → `<범위>` = `develop..HEAD`
- "이 커밋들만" → `<범위>` = 명시 범위
- "펜스 빼고" / "렌더되게" / "터미널에서 보게" → `--no-fence`

## 비고

- 섹션은 작업 성질에 맞게 가감 (인프라 변경 없으면 영향범위 단순화, 결정 없으면 7·8번 생략 등). **틀 강요 < 정확성**
- 표·체크박스·해시는 실제 git/대화에서 — 그럴듯한 채움 금지
- **자율 호출 자리는 지시다 — 다만 차단 장치는 없다.** description 에 적은 "순회를 마칠 때 / MR 본문이 필요한 자리" 는 이 스킬을 읽는 쪽이 **지켜야 하는 지시**다. 그와 별개로, 그 밖에서의 호출을 툴 레이어에서 막는 장치는 없다 — 막는 수단은 `disable-model-invocation` 하나뿐이고 그건 자율 호출을 통째로 차단해 자율 순회의 마지막 단계를 깨뜨린다. 그래서 쓰지 않는다
- 자율 호출로 부담이 없는 근거: 이 스킬은 읽기 전용이라 커밋·push·외부 전송이 없다. 잘못 불려도 손실은 출력 길이뿐이다
