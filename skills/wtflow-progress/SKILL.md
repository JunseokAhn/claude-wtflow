# /wtflow-progress — 워크트리 K 진행 현황

이슈 작업 항목(K)별 진행 상태를 표 하나로 보여준다. **읽기 전용** — git/glab 조회만 하고 어떤 변경도 하지 않는다.

## 호출

`/wtflow-progress [-N <이슈번호>] [-a <accumulator>] [--quiet]`

- 인자 없음(기본): 현재 워크트리 브랜치에서 이슈 번호·accumulator 자동 추론
- `-N <이슈번호>`: 이슈 번호 직접 지정(추론 실패 시)
- `-a <accumulator>`: accumulator 브랜치명 직접 지정(예 `feat/#19-sync-plan-limits-backend`)
- `--quiet`: 동기화 못 한 사유 등 부가 설명 생략하고 표만 출력(자율 호출 시 노이즈 최소화용)

## 데이터 소스 (이 셋만 신뢰)

K-모델의 contract 소스 **둘**을 합쳐 상태를 만든다. 추측 금지.

1. **이슈 `작업 항목` 체크리스트** — wtflow-commit 이 K 완료 시 체크하는 그 리스트. **위에서 N번째 항목 = K N**. `- [x]`=완료 신호.
2. **mirror 분기 `<prefix>/#<N>-<slug>-<KKK>`** — K 귀속의 **유일 소스**: 번호(뒤 3자리)=K, tip=그 K 최신 커밋. (커밋 메시지에 `K:` 트레일러 없음.)

> **어떤 mirror tip 의 조상도 아닌 dangling 커밋**은 K 단정 불가 → 표에 넣지 말고 **"미분류 커밋"** 줄로 노출(불변식 지켜지면 안 생김).

**활동 오버레이(K 귀속 소스 아님).** **미귀속 작업**(워킹트리 dirty **또는** 어떤 mirror 도 도달 못 하는 raw 커밋)이 있으면 활동 신호로 보고 **활성 K(절차 8 정의)를 `🟡 진행 중`** 으로 올린다(커밋된 진행 중과 합침, 별도 상태 안 둠). 단정 불가라 활성 K 한 곳에만 적용하고 파일 수·미분류 커밋은 표 아래로 노출(추정 표시). 정확한 귀속은 wtflow-commit 담당 — "커밋했는데 대기로 보이는" 착시 방지용 best-effort.

## 절차

1. **워크트리 확인** — `git rev-parse --show-toplevel` + `git worktree list`. main 워킹트리면 경고만 하고 진행(워크트리 전용은 아님, 이슈만 있으면 동작).
2. **이슈 번호 N 추론** — `-N` 우선. 없으면 현재 브랜치명에서 추출: accumulator `<prefix>/#<N>-<slug>` 의 `#` 뒤 정수(워크트리 브랜치 = accumulator = 이슈 마커). 추출 불가 → 표 없이 한 줄 안내(`-N` 으로 지정 요청) 후 종료.
3. **accumulator 추론** — `-a` 우선. 없으면 `git branch --list '*/#*' --format='%(refname:short)' | grep -vE -- '-[0-9]{3}$'` 중 현재 HEAD 와 ancestry 를 공유하는 것(wtflow-commit 컨벤션 — `-<KKK>` 로 끝나는 건 mirror 라 제외). 없으면 mirror 분기 조회만 skip(체크리스트만으로 표 구성).
4. **이슈 본문 조회** — `glab issue view <N> --output json` 으로 `description` 획득. 실패(인증/미존재) → 경고만 하고 종료.
5. **작업 항목 파싱** — `작업 항목`(또는 `작업 계획`) 섹션 안의 체크리스트를 **그 섹션 안에서** 순서대로 추출. 각 항목: 순번(=K) · 텍스트 · 체크 여부. 섹션이 없으면(한 줄 요약 이슈) → 표 대상 없음, 한 줄 안내 후 종료.
6. **mirror 분기 K 귀속** — `git branch --list '*/#<N>-<slug>-[0-9][0-9][0-9]'` 로 mirror 분기 수집. 각 분기: **번호(뒤 3자리)=K**, **tip=그 K 의 최신 커밋**(`%h %s`). mirror 가 있는 K = 잡힌 K. accumulator 미상(3번 skip)이면 mirror 없이 체크리스트만으로 표 구성.
7. **미분류 커밋 판정** — base 산정(`git merge-base HEAD origin/develop`, 없으면 develop→main) 후 `<base>..HEAD` 커밋 중 **어떤 mirror tip 의 조상도 아닌** 것을 미분류로 모은다(`git merge-base --is-ancestor <commit> <mirror-tip>` 로 각 mirror 에 대해 판정, 전부 실패면 미분류). 불변식 유지 시 0개.
8. **미귀속 작업 + 활성 K 산정** — `git status --porcelain`(dirty 여부·파일 수)와 7번의 미분류 커밋 유무를 본다.
   - **미귀속 작업 있음** = dirty **또는** 미분류 커밋 ≥1.
   - **활성 K** = ① `-K` 명시값, 없으면 ② 잡힌 K 중 **미완료(체크박스 [ ]) 최고 번호**(진행하던 K 이어감), 그것도 없으면 ③ 첫 ⬜ 대기 K(새로 시작). 잡힌 K·대기 K 가 전혀 없으면 활성 K 없음.
   - 미귀속 작업이 있고 활성 K 가 정해지면 그 K 를 진행 중 후보로 둔다(상태 판정에서 🟡 로 올림).
9. **note drift 점검** — `.claude/notes/<repo>/issue-<N>.md` 가 있으면 그 `K별 계약·위치` 표와 5번의 이슈 체크리스트를 대조한다. **이슈가 진실원이다.** 어긋나면:
   - **K 개수 불일치** — 이슈 항목이 늘거나 줄어 note 표의 행 수와 다름
   - **K 내용 이동** — 같은 번호인데 항목 텍스트가 가리키는 작업이 달라짐(항목 신설로 뒤 K 가 밀린 경우 포함)
   - **note 에만 있는 계약** — 이슈에서 빠졌는데 note K 로 남아 있음

   대조 결과는 10번 표 아래 `note drift` 줄로 노출한다. **여기서 note 를 고치지 않는다** — 이 스킬은 읽기 전용이다.
10. **상태 판정 + 표 출력** — 아래 규칙으로 K별 상태를 만들고 표 출력. **현재 진행 K** = 활성 K(없으면 잡힌 K 중 tip 이 가장 최근인 것(번호 최대 ≠ 최근 — K 커밋 순서가 번호와 다를 수 있음)).

## 상태 판정 규칙 (K i, 1-base)

"K i 에 커밋이 잡혔다" = mirror `-<i>` 분기가 있다(소스 2). 상태는 **완료/진행 중/대기 셋뿐** — "진행 중"은 귀속 커밋이 있든(mirror 분기) 미귀속 작업(활성 K & dirty/미분류 커밋)이든 하나로 합친다.

| 조건 | 상태 | 표기 |
|------|------|------|
| 체크리스트 `- [x]` | 완료 | ✅ 완료 |
| `- [ ]` + (커밋 잡힘 **또는** 활성 K & 미귀속 작업 있음) | 진행 중(귀속·미귀속·미커밋 무관) | 🟡 진행 중 |
| `- [ ]` + 그 외 | 미착수 | ⬜ 대기 |

- **완료(✅)는 dirty 여도 그대로** — 닫힌 K 에 무관한 변경이 있어도 되돌리지 않는다(활성 K 산정에서 완료 K 는 제외).
- **현재 K 표시**: 활성 K(절차 8 정의) 행 앞에 `▸`.
- **계획 외 K**: 체크리스트 항목 수보다 큰 K(mirror 분기)가 있으면 표 아래 `(계획 외 K{n}: <tip>)` 로 따로 한 줄. 추측해서 항목에 끼워 넣지 않는다.
- **미분류 커밋**(어떤 mirror tip 의 조상도 아닌 dangling 커밋): 어느 K 인지 단정 금지. 표 아래 `미분류 커밋 <n>개: <hash> <subject>…` 한 줄로 **반드시 노출**(`--quiet` 여도 — 귀속 미상임을 드러내려). 정확히 넣으려면 wtflow-commit 으로 커밋(= 해당 K mirror 를 tip 으로 전진)하라 안내.

## 출력 형식

```
## 진행 현황 — 이슈 #<N> <제목 한 줄>

| K | 작업 항목 | 상태 | 최신 커밋 |
|---|-----------|------|-----------|
| 1 | <항목 텍스트> | ✅ 완료 | `<hash> <subject>` |
| 2 | <항목 텍스트> | 🟡 진행 중 | `<hash> <subject>` |
| ▸ 3 | <항목 텍스트> | 🟡 진행 중 | — (작업 중) |
| 4 | <항목 텍스트> | ⬜ 대기 | — |

완료 <x>/<전체>  ·  현재 K<현재>
작업 중: <n>개 파일 변경        ← dirty 일 때만
note drift: K<n> <이슈 항목> ↔ note <note 쪽 내용>   ← 어긋날 때만
```

- 상태 범례: ✅ 완료 · 🟡 진행 중(커밋됐거나 편집 중) · ⬜ 대기. (세 상태뿐)
- 최신 커밋 열: 그 K 의 mirror 분기 tip 의 `%h %s`. 미귀속 작업으로만 진행 중인 활성 K 는 `— (작업 중)`(dirty) 또는 `— (미분류 <n>)`(미분류 커밋).
- dirty 면 요약 줄 아래 `작업 중: <n>개 파일 변경`. 미분류 커밋이 있으면 `미분류 커밋 <n>개: …` 줄도 둔다.
- **note drift(절차 9)는 어긋난 K 만 한 줄씩** — 이슈 쪽과 note 쪽을 나란히 적어 어디가 밀렸는지 보이게 한다. 표의 `작업 항목` 열은 **항상 이슈 텍스트**를 쓴다(note 를 섞지 않는다).
- 표 다음 줄에서 **"note 를 맞출까요?" 한 줄로 묻고 끝낸다.** 승인 없이 고치지 않는다.
- 제목·항목 텍스트가 길면 의미 보존하며 한 줄로 자른다.
- `--quiet` 면 표 + 요약 줄 + (있으면)작업 중·미분류·note drift 줄만, 그 밖의 부가 안내는 생략. **drift 줄은 `--quiet` 에서도 낸다**(미분류 커밋과 같은 이유 — 어긋난 걸 숨기면 다음 K 번호가 조용히 틀어진다). 다만 고칠지 묻는 건 사용자 호출 때만.

## 결정·skip 트리거 (걸리면 표 없이 한 줄 안내 후 종료, 추측 금지)

- 이슈 번호 추출 불가 → `-N <번호>` 로 지정 요청
- glab 인증/조회 실패 → 실패 사유 한 줄
- `작업 항목` 체크리스트 없음 → "체크리스트형 이슈 아님 — 진행 현황 대상 없음"
- 섹션/항목 순서 모호 → 추측 매핑 금지, 모호하다고만 보고

## wtflow-commit / wtflow-auto 연동 (자율 호출)

- **wtflow-commit**: 커밋·체크박스 동기화·요약을 마친 **직후** 이 스킬을 `--quiet` 로 1회 호출해 갱신된 K 표를 덧붙인다(자세히는 wtflow-commit 계약 8번).
- **wtflow-auto**: 커밋을 wtflow-commit 에 위임하므로 K마다 자동으로 이 표가 따라온다 — 별도 호출 불필요.
- 이 스킬이 종료(이슈 번호 추출 불가 등)해도 커밋 흐름은 막지 않는다 — 진행 가시성용 부가 출력일 뿐.

## 비고

- 읽기 전용·멱등·무부작용 — 아무 때나 여러 번 호출해도 안전. 상태는 데이터 소스(체크리스트·mirror 분기·워킹트리)에서만 파생, 커밋 메시지 추측 안 함. **note 도 읽기만 한다**(절차 9) — 이슈와 어긋나면 보고하고 묻되, 고치는 건 승인 후 별도 작업이다.
- note 는 **상태 소스가 아니다.** drift 점검은 계약 표(K별 계약·위치)가 이슈 항목과 같은 것을 가리키는지 보는 것뿐이고, 완료/진행 판정은 여전히 체크리스트·mirror 분기·워킹트리에서만 나온다.
