# /wtflow:mr — 작업 브랜치로 MR 생성·본문 재작성

**시작 전에 `${CLAUDE_PLUGIN_ROOT}/references/convention-precedence.md`(어디에 적힌 컨벤션이 우선하는지) 를 읽고, `pr-convention.md`(MR 제목·본문 형식)를 읽는다. `--rewrite` 면 `${CLAUDE_PLUGIN_ROOT}/references/body-rewrite.md`(본문 재작성 규율·훅 계약)도 읽는다.** 제목 규칙은 그 문서가 `commit-convention.md` 의 `## Subject` 를 가리키므로, 그것도 같은 순서로 찾는다.

작업이 끝난 브랜치를 origin 에 올리고 MR 을 연다. `/wtflow:merge` 와 **방향이 반대다**:

| | 방향 | 하는 일 |
|---|---|---|
| `/wtflow:merge` | 기본 브랜치 → 현재 브랜치 | 최신 기본 브랜치를 가져와 충돌을 해소해 커밋 |
| `/wtflow:mr` | 현재 브랜치 → 기본 브랜치 (요청) | origin 에 올리고 MR 을 열어 리뷰에 맡긴다 |

⚠️ 그래서 **이 스킬만이 기본 브랜치를 바꿀 수 있는 경로**다. 로컬에서 기본 브랜치에 직접 머지해
push 하면 리뷰를 건너뛴다 — 그 길을 쓰지 않는다.

## 호출

`/wtflow:mr [이슈번호] [-t <제목>] [-b <타깃>] [--draft] [--no-push]`

| 인자 | 뜻 |
|---|---|
| 생략 | 현재 워크트리의 accumulator 가 소스, 기본 브랜치가 타깃 |
| `<이슈번호>` | 그 이슈의 accumulator 를 소스로 (위치 무관) |
| `-t <제목>` | 제목 강제. 미지정 시 이슈 제목·커밋에서 유도 |
| `-b <타깃>` | 타깃 브랜치. 미지정 시 `develop`, 없으면 `main` |
| `--draft` | Draft MR 로 생성 |
| `--no-push` | push 를 건너뛴다(이미 올려둔 경우) |
| `--rewrite` | 생성이 아니라 **이미 열린 MR 의 본문 재작성** (아래 `## 재작성 모드`) |

## 계약 (보장되어야 하는 것)

1. **accumulator 를 origin 에 push 한다 — 규율의 예외다.** 워크트리 브랜치는 로컬 전용이고
   origin 에 노출되는 건 mirror 뿐이라는 규칙(`plan` 계약·`auto` 비고)의 **유일한 예외**가 이 스킬이다.
   MR 은 소스 브랜치가 origin 에 있어야 성립하고, 그 브랜치는 작업 전체를 담은 accumulator 여야 한다
   - **mirror(`-<KKK>`)를 소스로 쓰지 않는다** — Step 단위 조각이라 통짜 MR 이 안 된다
   - push 는 이 명령이 부를 때만. 다른 스킬은 여전히 accumulator 를 올리지 않는다
   - 되돌리기: MR 을 닫고 `git push origin --delete '<accumulator>'`
2. **제목은 `pr-convention.md` 의 `## 제목` 을 따른다** — 커밋 컨벤션의 `## Subject` 그대로이고,
   이슈가 있으면 이슈 제목을 그대로 쓰는 것이 기본이다
3. **force-push 하지 않는다.** 이미 올라간 브랜치가 갈라져 있으면 멈추고 보고한다

4. **이미 열린 MR 이 있으면 만들지 않는다** — 먼저 확인한다:
   ```
   glab mr list -s '<accumulator>'
   ```
   있으면 그 URL 을 보고하고 끝낸다(중복 MR 을 만들지 않는다). **본문·제목을 갱신할지는 사용자
   결정이고, 갱신하기로 했으면 `--rewrite` 로 이 스킬을 다시 부른다** — `## 재작성 모드`

5. **반영 → push → 생성 순서를 지킨다** — 뒤집지 않는다:
   ```
   Skill(wtflow:merge)                              ← 기본 브랜치 최신본을 먼저 흡수
   git push -u origin '<accumulator>'
   glab mr create -s '<accumulator>' -b <타깃> …
   ```
   - **`/wtflow:merge` 를 먼저 부른다.** 기본 브랜치가 앞서 있으면 리뷰어가 이 작업과 무관한
     충돌까지 보게 된다. 가져올 게 없으면 `Already up to date.` 로 아무것도 하지 않으므로
     **항상 불러도 안전하다** — 뒤처졌는지 미리 재보고 조건부로 부르지 않는다
   - ⚠️ **머지가 깨끗이 끝나지 않으면 MR 을 만들지 않는다.** 충돌이 남았거나 wtflow:merge 의
     빌드 검증이 실패하면 그 상태를 보고하고 멈춘다. 반쯤 머지된 브랜치를 올리면 리뷰가 성립하지 않는다
   - 머지 규칙(메시지 형태·기준 브랜치 판정·충돌 해소·검증)은 **전부 wtflow:merge 의 계약**이다.
     여기에 다시 적지 않는다 — 두 벌이 되면 한쪽만 고쳐져 어긋난다
   - **merge 가 되물으면 그 자리에서 멈춘다** — 로컬 기본 브랜치와 원격이 갈리면 merge 계약 7 이
     어느 쪽을 기준으로 삼을지 묻는다. MR 을 만드는 흐름이라고 해서 임의로 고르고 지나가지 않는다.
     잘못 고른 기준은 그대로 리뷰에 올라간다
   - glab 의 `--push` 는 **MR 을 만든 뒤** 올리므로 쓰지 않는다. 생성 시점에 소스 브랜치가 이미
     origin 에 있어야 타깃 대비 diff·충돌을 판단할 수 있다
   - `--create-source-branch` 도 쓰지 않는다 — 커밋 없는 빈 브랜치가 올라갈 수 있다

6. **비대화형으로 부른다 — `-y` 와 `--no-editor` 를 반드시 붙인다.**
   ```
   glab mr create -s '<accumulator>' -b <타깃> -t "<제목>" -d "<본문>" -y --no-editor
   ```
   ⚠️ 빼면 glab 이 제목·본문·확인을 입력받으려 기다리는데, **이 명령에는 사용자 입력이 도달하지
   않는다**(터미널이 아니라 도구를 통해 실행되므로). 멈춘 채 타임아웃되거나 빈 값으로 통과한다

7. **이슈가 있으면 `-i <이슈번호>` 를 함께 넘긴다** — MR 과 이슈가 엮이고, `-t` 가 없으면 제목을
   이슈에서 가져온다. `-t` 가 주어지면 그것이 우선한다
   - 라벨을 이슈에서 가져오려면 `--copy-issue-labels` 를 붙인다(`-i` 와 함께만 동작)

8. **`--draft` 는 사용자가 줬을 때만.** 임의로 Draft 로 만들지 않는다

9. **본문은 브리핑에서 얻는다 — `--mr --no-fence` 로 부른다.** 범위는 accumulator 의 base..HEAD:
   ```
   Skill(wtflow:briefing) → /wtflow:briefing <base>..HEAD --mr --no-fence
   ```
   - `--mr` 은 MR description 압축본이다. **형식과 분량은 `pr-convention.md` 가 정한다** —
     저장소 MR 템플릿이 있으면 그 섹션 구성이 우선하고, 없으면 플러그인 기본 템플릿. 본문 40줄 상한.
     여기 사본을 두지 않는다(사본은 어긋난다)
   - ⚠️ **받은 본문을 그 상한과 대조하고 넘으면 다시 쓴다.** `Skill()` 은 브리핑을 만들어
     돌려주는 게 아니라 **지시문을 로드하고 제어를 되돌려주는** 것이라, 여기서 세지 않으면
     형식을 검사하는 지점이 아예 없다. 대화에 쌓인 근거를 압축 없이 그대로 옮겨 길어지는 것이
     가장 흔한 실패다
   - ⚠️ **`--no-fence` 가 필수다.** 브리핑 기본값은 출력 전체를 하나의 코드펜스로 감싸는 것이라,
     그대로 넘기면 MR 본문에 펜스가 그대로 박혀 렌더가 깨진다
   - 브리핑은 자율 호출이 허용돼 있다("MR 본문이 필요한 자리에서는 `--mr` 로 자율 호출")

10. **본문은 파일을 거쳐 넘긴다** — glab 에는 본문 파일 옵션이 없고 `-d` 문자열뿐이다:
    ```
    glab mr create … -d "$(cat <본문파일>)"
    ```
    본문에 줄바꿈·백틱·따옴표가 섞이므로 **인자에 직접 이어붙이지 않는다**

11. **브리핑을 못 얻으면 MR 을 만들지 않는다.** 빈 본문이나 손으로 지어낸 요약으로 대체하지 않는다
    — 사유를 보고하고 멈춘다. 본문 없는 MR 은 리뷰가 성립하지 않는다

## 재작성 모드 (`--rewrite`)

이미 열린 MR 의 **본문(필요하면 제목)을 다시 쓴다.** 계약 4 가 손을 떼던 자리를 이 모드가 받는다
— 갱신할지 말지는 여전히 사용자 결정이고, 결정한 뒤의 **쓰기**가 스킬 안으로 들어온다.

⚠️ **MR 본문을 바꾸는 경로는 이것 하나다** — 규율은 `body-rewrite.md` 가 갖는다.

`/wtflow:mr --rewrite [이슈번호] [-t <제목>] [--iid <MR iid>]`

- 대상 MR: `--iid` 가 있으면 그것, 없으면 계약 4 의 `glab mr list -s '<accumulator>'` 결과
- **0개면 중단** — 없는 MR 을 재작성할 수 없고, 만들지도 않는다(만들 거면 `--rewrite` 없이 부른다)
- **2개 이상이면 되묻는다** — 엉뚱한 MR 을 덮어쓰지 않는다

### 계약을 어디까지 다시 타나

| 생성 계약 | 재작성에서 |
|---|---|
| 1 accumulator push | **적용 안 함** — 이미 올라가 있다. 새 커밋을 올릴 거면 `--rewrite` 없이 부른다 |
| 2 제목 규칙 | **제목을 바꿀 때만**(`-t`). 안 주면 건드리지 않는다 |
| 3 force-push 금지 | 그대로 |
| 4 중복 MR 방지 | **전제가 뒤집힌다** — 열린 MR 이 있어야 성립한다 |
| 5 반영→push→생성 순서 | **적용 안 함** — 이미 올라간 브랜치의 본문만 고친다. 커밋을 새로 올릴 거면 `--rewrite` 없이 부른다 |
| 6 비대화형 | 그대로 — `WTFLOW_BODY_REWRITE=1 glab mr update <iid> -d "$(cat <본문파일>)" [-t "<제목>"]` |
| 7 이슈 연결 | 이미 엮여 있다. `-i` 를 다시 주지 않는다 |
| 8 draft | 적용 안 함 (draft 전환은 `--draft`/`--ready` 로 별개) |
| 9 본문 = 브리핑 압축본 | **그대로 적용** — 아래 |
| 10 본문은 파일 경유 | 그대로 |
| 11 브리핑 없으면 안 만듦 | **그대로 — 손으로 지어낸 요약으로 기존 본문을 덮어쓰지 않는다** |

⚠️ **6 의 `WTFLOW_BODY_REWRITE=1` 환경변수를 빼지 않는다** — 이유와 금지 사항은
`body-rewrite.md` 의 `## WTFLOW_BODY_REWRITE=1 을 빼지 않는다`. 이 스킬에서 "실제로 거친 뒤" 란
**브리핑 재수집·상한 재검사·확인**을 마친 뒤다.

### 본문은 옛 본문을 손보는 게 아니라 다시 받는다

재작성이 필요한 이유는 대개 **커밋이 더 쌓였기 때문**이다. 그러니 현재 범위로 브리핑을 다시 받아
통째로 갈아끼운다:

```
Skill(wtflow:briefing) → /wtflow:briefing <base>..HEAD --mr --no-fence
```

- 형식·분량은 `pr-convention.md` 가 정한다. **여기 사본을 두지 않는다**
- ⚠️ **받은 본문을 상한과 대조하고 넘으면 다시 쓴다.** 계약 9 와 같은 이유이고, **재작성에서 더 잘
  깨진다** — 그 시점엔 대화에 근거가 잔뜩 쌓여 있어 "버리기 아깝다" 가 세진다
- 사용자가 특정 섹션만 고치라고 지목했으면 그 섹션만 고친다. 그때도 상한은 다시 센다

### 확인 질문

**질문 축은 "본문 이대로 반영할지" 다.** 확인 방식과 다시 쓰는 조건은 `body-rewrite.md` 의
`## 미리보기에는 셀 수 있는 변화를 낸다`. MR 에서 세는 것은 이 넷이다:

| 항목 | 형태 |
|---|---|
| 헤더 | `템플릿과 같음`, 어긋나면 어긋난 이름을 전부 |
| 줄 수 | `31줄 → 38줄 (+7)` — 상한 40줄 대비 |
| 커밋 나열 섹션 | `4줄 / 커밋 5개` — 어긋나면 그대로 표시 |
| 제목 | `변경 없음` 또는 `이전 → 이후` |

- 상한 40줄은 `pr-convention.md` 의 `## 셀 수 있는 상한` 이 정한다
