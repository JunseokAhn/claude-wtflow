# /wtflow:clean — 워크트리·브랜치 정리

**참조 문서를 읽지 않는다.** 다른 스킬과 달리 이 스킬은 브랜치 이름 규칙을 적용하지 않는다 —
역추적·mirror 매칭·보존 판정은 전부 스크립트 안에 있다. 필요한 한 가지 사실만 여기 적어 둔다:

> accumulator(=워크트리 브랜치)는 이슈 작업이면 `<prefix>/#<N>-<slug>`, 이슈 없는 작업이면
> `<prefix>/+<slug>` 이고, mirror 는 그 뒤에 `-<KKK>`(3자리)가 붙은 것이다.

작업이 끝난 워크트리와 거기 딸린 accumulator·mirror 를 지운다. 실제 삭제는 `wtflow-clean`
스크립트가 하고, 이 스킬은 **받은 인자를 그대로 넘겨 한 번 실행하고 그 출력을 원문으로
옮기는 역할**만 맡는다.

**확인을 덮지 않는다.** 이 명령은 사용자만 호출할 수 있고(`disable-model-invocation`), 호출
자체가 이미 삭제 의사 표시다. 그 위에 미리보기와 승인을 한 겹 더 얹으면 얻는 안전은 없고
왕복만 늘어난다 — 위험한 상황에서 멈추는 일은 스크립트가 자기 안에서 한다(미보존 브랜치
건너뜀, 더러운 워크트리 보류, 머지 실패 시 전면 중단).

## 호출

`/wtflow:clean [이슈번호 | 작업이름 | 작업브랜치 …] [옵션…]`

사용자가 준 인자는 손대지 않고 `wtflow-clean` 에 그대로 넘긴다. **생략했을 때만 계약 1 이
대상 브랜치 이름을 채워 넣는다.** 전체 옵션은 `wtflow-clean -h` 에 있고, 자주 쓰는 것만
옮기면 다음과 같다.

| 인자 | 뜻 |
|---|---|
| 생략 | 워크트리 안에서 부르면 그 워크트리가 대상 — 계약 1 이 나가기 전에 브랜치 이름을 읽어 넘긴다 |
| `42` | 이슈 42 의 브랜치·워크트리를 위치와 무관하게 역추적 |
| `dark-mode` | 이슈 없는 작업을 **작업 이름만으로** 지목 (접두사 불필요 — `<prefix>/+dark-mode` 를 찾아준다). 하나로 좁혀지지 않거나 없는 이름이면 스크립트가 중단한다 |
| `fix/#42-foo` | 브랜치명을 그대로 줘도 된다 (있는 브랜치면 그 이름을 쓴다) |
| `17 19 dark-mode` | 여러 대상을 한 번에. 대상마다 따로 처리하고 하나가 실패해도 나머지는 계속한다 — 끝에 대상별 성공·실패를 모아 낸다 |
| `develop` · `main` | 거부된다. 기본 브랜치는 명시해도 삭제 대상이 되지 않는다 |
| `-m` | mirror(`-NNN`)만 삭제. 워크트리 브랜치는 남긴다 |
| `-w` | 워크트리만 제거. 브랜치는 남긴다 |
| `-M` | 삭제 전에 기본 브랜치로 머지. 머지 실패면 아무것도 안 지운다 |
| `-f` | 미병합 브랜치·더러운 워크트리까지 강제 |

## 계약 (보장되어야 하는 것)

1. **나가기 전에 대상을 붙잡는다** — 현재 세션이 삭제 대상 워크트리 안에 있으면, 나오기 **전에**
   대상 브랜치 이름을 읽어 두고 그것을 인자로 넘긴다.
   ```
   git rev-parse --abbrev-ref HEAD          # 예: fix/#18-clean-target-resolution
   ExitWorktree({ action: "keep" })
   wtflow-clean "<위에서 읽은 이름>" -y
   ```
   - ⚠️ **인자 없이 부르지 않는다.** 스크립트의 "인자 생략 = 현재 브랜치" 는 셸에서 워크트리 안에
     선 채로 부를 때를 위한 규칙이다. 이 스킬은 그 전에 워크트리를 빠져나오므로, 그 시점의
     "현재 브랜치" 는 메인 체크아웃의 브랜치 — 대개 기본 브랜치다. 실제로 그렇게 `develop` 이
     삭제 대상으로 잡힌 적이 있다
   - **읽는 값은 브랜치 이름이다.** 이슈번호로 넘기면 스크립트가 역추적을 한 겹 더 하게 되어
     "스킬이 본 것" 과 "스크립트가 찾은 것" 이 갈릴 수 있다. 사용자가 번호·slug 를 직접 줬으면
     그건 그대로 넘긴다(계약 4) — 고정이 필요한 건 **인자를 안 받았을 때**뿐이다
   - **대상 판정** — 인자를 생략했거나, 인자가 현재 accumulator 의 이슈번호·slug 와 일치하면
     현재 워크트리가 대상이다. `-m`(mirror 전용)이면 워크트리는 남으므로 나오지 않는다
   - 순서를 뒤집어 스크립트를 먼저 돌리면 삭제는 성공하지만 셸이 사라진 디렉토리에 남는다
   - `action` 은 **항상 `keep`**. `remove` 를 쓰지 않는다 — ⓐ wtflow 워크트리는 `git worktree add`
     로 만들어져 있고 이 툴은 자기가 만든 워크트리만 건드린다(그래서 애초에 안 지워진다)
     ⓑ mirror 분기(`-00N`)와 accumulator 를 지우지 못한다 ⓒ dirty·미보존 판정 기준이
     스크립트와 갈린다. 삭제는 전부 스크립트 몫이다
   - 이 툴은 원래 사용자가 이탈을 요청할 때만 쓰는 것이지만, **`/wtflow:clean` 호출 자체가
     "이 워크트리를 치워달라" 는 요청**이므로 그 안에 이탈 요청이 포함된 것으로 본다
2. **한 번만 실행한다** — 받은 인자에 `-y` 를 붙여 곧장 실행한다. 미리보기 실행도, 승인 질문도
   없다. 사용자가 `-n` 이나 `-h` 를 직접 줬으면 그것만 실행하고 끝낸다(그 경우 `-y` 를 붙이지 않는다)
   - `-y` 를 **반드시 명시**한다. 붙이지 않아도 결과는 같지만, 그건 스크립트의 `[Y/n]` 이 읽을
     입력 통로가 없어 빈 답으로 통과되는 **우연**에 기대는 것이다. `-y` 는 그 결과를 선언으로 바꾼다
3. **출력을 원문으로 옮긴다** — 삭제 대상·건너뜀·실패 줄을 요약하거나 추려서 옮기지 않는다.
   무엇이 사라졌는지는 사용자가 스크립트의 말로 봐야 한다
4. **옵션은 지어내지 않는다** — 사용자가 안 준 `-f`·`-M` 을 임의로 붙이지 않는다.
   출력이 "미보존이라 건너뜀" 을 보고하면 그 사실을 전하고 `-f`/`-M` 중 무엇을 쓸지 묻는다
   - 덧붙이는 것은 `-y`(계약 2)와, **인자를 생략했을 때의 대상 브랜치 이름**(계약 1) 둘뿐이다.
     둘 다 옵션이 아니라 "무엇을 어떻게 지울지" 를 바꾸지 않는 값이다 — `-f`·`-M` 은 안전장치를
     끄는 것이라 성격이 다르다
5. **삭제 대상이 없으면 거기서 끝낸다** — 스크립트가 "삭제할 대상이 없습니다" 를 내면 그대로 보고하고
   종료한다. 다른 이슈번호를 추측해 다시 시도하지 않는다
6. **origin 은 건드리지 않는다** — 스크립트가 이미 로컬 전용이다. 이 스킬도 push·MR 을 하지 않는다

## 결정·중단 트리거

- 현재 세션이 **지우려는 워크트리 안에 있다** → 중단이 아니다. 계약 1대로 먼저 빠져나온 뒤 실행한다
- `ExitWorktree` 가 실패했다 → **거기서 멈춘다.** 세션을 못 뺀 채로 지우면 셸이 사라진 디렉토리에
  남는다. 사유를 전하고, 사용자가 직접 다른 디렉토리로 이동한 뒤 다시 부르게 한다
- 워크트리에 커밋 안 된 변경이 있다 → 스크립트가 목록을 보여주고 멈춘다. 임의로 `-f` 를 붙이지 말고
  이관·강제·건너뜀 중 무엇을 할지 묻는다
- 대상 브랜치가 미병합이다 → `-f`(그냥 버림)와 `-M`(기본 브랜치로 머지 후 삭제)은 결과가 전혀 다르다.
  둘 중 하나를 고르게 한다
- 이슈번호도 브랜치도 특정되지 않는다 → 묻고 중단한다
- 스크립트가 "찾지 못했습니다"·"여럿입니다"·"이슈번호로 지정하세요" 로 중단했다 → **그 메시지를 그대로
  전하고 멈춘다.** 비슷한 이름을 추측해 다시 부르지 않는다 — 이름이 안 맞았다는 사실 자체가 정보다

## 짧은 변형

- "미러만 치워" → `-m` · "워크트리만 지워" → `-w`
- "머지하고 정리해" → `-M` · "그냥 다 지워" → `-f`
- "뭐 지워지는지만 보여줘" → `-n` 만 실행하고 종료 (`-y` 안 붙임)

## 비고

- 스크립트 본체는 `${CLAUDE_PLUGIN_ROOT}/bin/wtflow-clean` 이다. 로직을 이 스킬에 옮겨 적지 않는다
  — 옵션이 늘거나 바뀌면 스크립트 하나만 고치면 되게 둔다
- **PATH 범위** — 플러그인은 `bin/` 을 **Claude Code 가 실행하는 셸의** PATH 에만 올린다. 그래서
  이 스킬은 `wtflow-clean` 을 맨 이름으로 부를 수 있지만, **사용자의 터미널에는 자동으로 등록되지
  않는다**(그쪽은 별개 프로세스라 그 환경변수를 물려받지 않는다). 사용자가 셸에서 직접 쓰고 싶다면
  PATH 에 있는 디렉토리로 심링크를 걸어야 한다 — 안내는 README 에 있다
- 정리 후 남은 워크트리 목록은 `git worktree list` 로 확인한다
