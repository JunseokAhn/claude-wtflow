# /wtflow-merge — 작업 브랜치를 develop 으로 머지

## 호출

`/wtflow-merge [이슈번호…] [-r <repo>…]`

인자 없으면 현재 맥락의 마일스톤 관련 브랜치를 대상으로 삼되, **범위를 먼저 표로 보고**한다.

## 계약

1. **대상은 `git branch --no-merged develop` 로 확정한다.** 이슈 체크박스·브랜치 이름으로 추정하지 않는다.
   `main`·`local/*`·무관한 옛 브랜치는 **제외**하고, 무엇을 왜 뺐는지 보고한다.
2. **머지 대상·메시지는 워크트리 브랜치(= accumulator = 이슈 마커) 이름으로 적는다** —
   mirror(`<prefix>/#N-slug-00K`)나 임시 통합 브랜치 이름을 쓰지 않는다.
   accumulator 는 커밋마다 전진하므로 그 이슈의 모든 K 를 이미 담고 있다:
   ```
   git merge --no-ff '<prefix>/#<N>-<slug>'
   ```
   기본 메시지가 곧 `Merge branch '<prefix>/#<N>-<slug>' into develop` 이라 `-m` 이 필요 없다.
   - accumulator 가 없을 때만(워크트리를 이미 지웠거나 레거시 `worktree/#N-slug`) **최종 K 의
     mirror tip 을 머지하고 메시지만 마커 이름으로** 적는다:
     ```
     git merge --no-ff '<prefix>/#<N>-<slug>-<최종 K>' \
       -m "Merge branch '<prefix>/#<N>-<slug>' into develop"
     ```
   - ⚠️ **레거시 `worktree/#N-slug` 는 이름 그대로 머지 메시지에 쓰지 않는다** — `<prefix>/` 이름으로
     바꿔 적는다
3. **`--no-ff` 고정.** 머지 커밋이 남아야 어느 이슈가 언제 들어갔는지 이력에 보인다.
4. **여러 이슈는 번호 오름차순**으로 하나씩. 한 번에 octopus 머지하지 않는다 — 충돌이 뭉쳐 못 푼다.
5. **충돌 해소 후 빌드로 검증한다.** 해소가 끝이 아니다:
   컴파일 언어 → `compileJava`/`compileTestJava` 등, TS → `npx tsc --noEmit`, Python → 구문 파싱.
   깨지면 커밋하지 않고 보고한다.
6. **push 하지 않는다.** origin 반영·MR 은 사용자 결정.

## develop 을 어디서 꺼낼 것인가 (가장 흔한 사고 지점)

머지 전에 `git worktree list` 로 develop 이 **이미 체크아웃돼 있는지** 본다.

| 상황 | 처리 |
|---|---|
| develop 이 메인 체크아웃에 나와 있음 | 거기서 머지. 단, `status --porcelain` 로 클린 확인 |
| develop 이 아무 데도 없음 | **임시 워크트리**에 붙여 머지하고, **끝나면 반드시 제거** |
| develop 이 다른 워크트리에 물려 있음 | 그 워크트리에서 머지 |

⚠️ **임시 워크트리를 남기면 develop 이 그 워크트리에 점유돼 사용자가 메인에서 develop 을 못 꺼낸다.**
머지 커밋은 워크트리가 아니라 **develop ref** 에 들어가므로, 워크트리를 지워도 커밋은 남는다.
작업이 끝나면 `git worktree remove` 까지가 한 단위다.

## 충돌 해소 감각

- **import·목 선언 충돌은 대개 "양쪽 다 필요"** 다. 한쪽을 버리기 전에 그 심볼이 정말 안 쓰이는지 본다.
- **한쪽이 다른 쪽의 구형을 들고 오는 경우**가 있다(브랜치를 딴 시점이 달라서). 최신 정의를 살리고
  구형 중복을 버린다 — 어느 쪽이 최신인지는 `git log` 로 확인하고 추측하지 않는다.
- **같은 문제를 다르게 고친 두 브랜치**가 부딪히면 한쪽을 기계적으로 취하지 말고,
  **실제로 검증된 쪽을 기본으로 삼고 다른 쪽의 고유 기여만 흡수**한다. 그 판단 근거를 보고에 적는다.
- 테스트 파일 충돌은 런타임에 영향이 없더라도 **버리지 말고** 양쪽 케이스를 살린다.

## 중단 트리거

- 대상 브랜치 판별이 모호(accumulator 없음 + mirror 여러 갈래) → 묻는다
- 충돌 해소에 **제품 결정**이 필요(둘 중 어느 설계를 남길지) → 선택지 제시 후 대기
- 빌드·타입 검사 실패 → 커밋하지 않고 보고
- 다른 레포까지 번짐 → 레포별로 나눠 보고하고 진행
- **세션이 워크트리에 격리돼 같은 레포의 공유 체크아웃을 못 건드림** → 우회하지 말고,
  사용자가 실행할 명령을 그대로 적어 넘긴다
