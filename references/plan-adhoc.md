# plan — 이슈 없는 작업(adhoc)

`/wtflow:plan "<작업 설명>"` 처럼 **인자가 문장일 때만** 필요한 절.
**`plan` 이 adhoc 으로 판정했을 때 읽는다** — 이슈 번호로 부른 호출은 읽지 않는다.

계약·plan 출력 형식은 `skills/plan/SKILL.md`, 재플랜은 `plan-replan.md` 를 본다.

## adhoc 작업 시작

이슈를 만들 만큼 정리되지 않았거나 만들 이유가 없는 작업을, **K 분해와 커밋 규율은 그대로 두고**
바로 시작한다. 이슈 본문이 하던 일(목표·범위·작업 항목)을 **질문 + 코드 분석**이 대신한다.

1. **묻기 전에 코드를 먼저 본다** — 작업 설명에서 키워드를 뽑아 Glob/Grep. **코드로 답이 나오는 건
   묻지 않는다.** 질문은 코드에 안 적힌 것(의도·범위·완료 기준)만
2. **필요한 것만 한 번에 묻는다** — `AskUserQuestion` 1회, **최대 3문항**. 보기 첫째가 추천안 `(추천)`.
   자유 입력은 자동 "Other" 로 보장되니 "직접 입력" 보기는 넣지 않는다

   | 질문 | 언제 | 안 물을 때 |
   |---|---|---|
   | **범위·완료 기준** (포함/제외) | 거의 항상 — adhoc 의 핵심 결손 | — |
   | prefix / 작업 성격 | 설명으로 성격이 안 드러날 때만 | 추론 ("추가"→`feat`, "안 됨"→`fix`) |
   | base 브랜치 | `origin/develop` 이 없거나 다른 흐름을 시사할 때만 | `origin/develop` |
   | 접근 방식 | 갈래가 둘 이상이고 K 분해가 달라질 때만 | 안 물음 |

   ⚠️ **"이슈를 만들까요?" 는 묻지 않는다** — 이슈 없이 시작하겠다고 이미 고른 것이다
   (나중에 필요하면 `## 이슈로 승격`)
3. **확정 요약 3줄** — 목표 / 범위(제외 포함) / prefix·base·브랜치명
4. 이후 계약 3·4·5 → 6~8 은 이슈 작업과 **동일**. plan 표의 Step = K 이고, **그 표가 곧 작업
   항목 목록이다** — 따로 적어두는 파일은 없다

### adhoc 의 작업 항목은 어디 사나

이슈 본문이 없으니 체크박스를 둘 곳도 없다. 대신 **둘이 함께** 그 자리를 맡는다:

| | 무엇을 담나 | 언제까지 사나 |
|---|---|---|
| **이 세션의 plan 출력** | 항목 텍스트·범위·관련 파일 | 세션이 사는 동안 |
| **mirror 분기 `<accumulator>-<KKK>`** | K 번호·귀속 커밋·진행 여부 | 영구(git) |

- **진행 상태의 진실원은 mirror 분기다.** `-<KKK>` 가 있으면 그 K 는 시작된 것, tip 이 최신 커밋.
  `wtflow:commit --done` 은 켤 체크박스가 없어 **이슈 작업 전용**이다
- 세션이 끊기면 항목 텍스트는 복구되지 않는다. K 번호와 커밋은 남으므로 `/wtflow:plan` 을 다시
  불러 잔여 항목만 새로 세운다(`plan-replan.md`)
- 계약 note 가 필요하면 그 경로를 직접 알려준다(계약 6-c) — adhoc 은 이슈가 없어 자동으로 못 찾는다

### 이슈로 승격

작업 도중 이슈로 올려야겠다 싶으면 `/wtflow:issue` 로 이슈를 만든 뒤 **이름만 갈아끼운다**
(작업물·커밋은 그대로). **사용자 요청 시에만.**

```
git branch -m '<prefix>/+<slug>' '<prefix>/#<N>-<slug>'            # accumulator
git branch -m '<prefix>/+<slug>-001' '<prefix>/#<N>-<slug>-001'    # mirror 전부
```

그리고 **현재 plan 표의 작업 항목을 이슈 본문 체크리스트로 옮긴다** — 이미 커밋된 K(mirror 가 있는
번호)는 `- [x]` 로. 이 순간부터 진실원이 이슈로 넘어가고, `--done` 이 동작하기 시작한다.
