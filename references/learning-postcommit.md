# 사전문답 — 작업 항목을 닫는 커밋 뒤

작업 항목을 **닫는 커밋 뒤에** 묻는 절 둘을 담는다 — 그 항목에서 무엇이 달라졌나(§11 의도 재확인)와
그 코드가 어떻게 도나(§7 코드 퀴즈).
**`commit`·`auto` 가 시작 전에 읽는다.**

질문 형식·질문 전 검사는 `learning-protocol.md`, 구현 Step 안의 문답은
`learning-implementation.md`, 방향·커밋 경계는 `learning-direction.md` 를 본다.

⚠️ **여기 두 절은 작업 항목 경계의 한 번의 호출에 함께 담긴다** — 다음 Step 진행 여부·착수 전 질문과
같은 창이다(`## 한 호출에 담는다`).
번호가 §7·§11 로 떨어진 것은 절을 새로 끼워도 다른 문서의 참조가 안 밀리게 하려는 것뿐이다.

## 언제 — 커밋마다가 아니라 작업 항목을 닫을 때

| 커밋 | 묻나 |
|---|---|
| 작업 항목을 닫기 전 커밋 | ❌ 묻지 않는다 — 소재·동작 변화는 닫을 때 모아 본다 |
| **작업 항목을 닫는 커밋** | ✅ 그 항목의 커밋 전부를 두고 묻는다 |
| `/wtflow:auto` 순회 안의 닫는 커밋 | ❌ 그 자리에선 묻지 않는다 — **순회가 끝난 뒤 모아 묻는다**(`## 순회가 끝난 뒤 모아 묻는다`) |

- **닫는 커밋** : `--done` 을 단 커밋. `--done` 없이 다음 Step 으로 넘어가면 `wtflow:commit` 계약 6 이
  앞 Step 을 닫는 그 커밋이고, 묻는 대상은 앞 Step 이다
- **묻는 범위** : 그 Step 에 쌓인 커밋 전부 — 직전 Step 의 mirror tip 부터 닫는 커밋까지
  (첫 Step 이면 accumulator 의 base 부터)
- 이슈 없는 작업도 같다 — 체크박스가 없을 뿐 `--done` 이 닫는 신호인 것은 그대로다

**Why:** 멈추는 자리는 작업 항목 경계 하나뿐인데(`worktree-discipline.md` 의 `### 멈추는 자리는 하나뿐`)
커밋 직후 질문만 커밋마다 멈췄다. 커밋 하나만 보고 묻는 의도 재확인은 그 커밋이 작업 항목의
어느 단계인지도 알 수 없었다(#61 — 첫 커밋 「외부 id 채우기」 직후에 나간 질문).

## 7. 코드 퀴즈 — 그 항목에서 커밋한 코드의 동작을 맞힌다

**목적은 코드를 읽는 힘이다.** 언어·프레임워크 규칙이 결과를 정하는 자리를 짚어, 다음에 같은
모양을 볼 때 코드가 읽히게 한다. 항목을 닫을 때 내는 이유는 다음 항목이 그 코드를 덮기 전이어서다.

- **정답이 하나여도 낸다** — §1 예측 퀴즈·§5 이해 퀴즈와 목적이 다르다. `learning-protocol.md` 의
  "정답이 하나인 것은 대상이 아니다" 는 **그 두 절에만** 걸린다
- **소재가 있을 때만 낸다** — 없으면 그 항목은 코드 퀴즈 없이 닫힌다(`### 소재를 거르는 기준`)
- **Step 당 1건.** 같은 Step 에 커밋이 여럿이어도 문항은 하나다 — `/wtflow:auto` 순회 끝에서는
  **순회 전체에서 1~2건**이다(`## 순회가 끝난 뒤 모아 묻는다`)

### 소재를 거르는 기준

**짜내지 않는다.** 아래 왼쪽이 있을 때만 내고, 없으면 안 낸다.

| 낸다 — 규칙이 결과를 정하는 자리 | 안 낸다 |
|---|---|
| effect·클로저가 잡는 값, 의존성 배열 | 이름·주석·포맷·문구 |
| 참조 동일성(매번 새로 만들어지는 객체·배열·함수) | 저장소에서 이미 여러 번 쓴 관용구의 반복 |
| 예외·에러가 분류되는 경로 | 값만 바꾼 설정·상수 |
| 타입이 좁혀지거나 넓혀지는 자리 | **여러 파일을 오가며 상태를 쫓아야 답이 나오는 것** — 그건 버그 추적이다 |
| 비동기 순서·수명(언제 실행되고 언제 비워지나) | 사용자가 직접 쓴 코드(§2 사용자 작성) |

- **소재가 없으면 "없다" 고 한 줄 적고 넘어간다** — 조용히 건너뛰면 낸 것과 구분이 안 된다
- 판정이 애매하면 **안 내는 쪽**이다. 억지 문항 하나가 다음 문항까지 습관적으로 넘기게 만든다

### 형식

`AskUserQuestion` 단일 선택. **`(추천)` 을 붙이지 않는다** — 맞히는 자리다.

- **그 항목에서 커밋한 코드 3~10줄을 인용한다.** 답에 필요하면 diff 밖도 인용한다 —
  `learning-protocol.md` 의 검사 ③·④ 가 그대로 걸린다
- **인용 자리는 §1 예측 퀴즈 `### 어디에 두나`** — preview 에 안 들어가면 턴 끝 응답에 두고
  알림으로 재개해 묻는다. 항목을 닫을 때 인용은 여러 덩이라 대개 이쪽이다
- 질문 본문에 인용한 코드가 든 **commit hash** 를 적는다 — `git show <hash>` 로 열어 보게
- 보기 3~4개. 오답도 그럴듯해야 한다 — 한눈에 틀린 보기는 답을 알려주는 것과 같다
- 답을 받으면 **그 자리에서 정답과 근거 한 줄.** 갈리면 실행해서 결론낸다

### 코드 버그는 문항이 아니다

깨지는 자리를 찾는 것은 실행·테스트로 확인되는 일이라 **내 몫이다.**

- 찾으면 **같은 Step 의 다음 커밋으로 고친다** — 무엇을 고쳤는지는 그 커밋 메시지가 설명한다
- **문항으로 내지 않고, 따로 보고도 하지 않는다** — 커밋 메시지에 이미 남는다
- 테스트가 그 자리를 덮고 있으면 `wtflow:commit` 계약 2(테스트 회귀)가 먼저 막는다

## 11. 의도 재확인 — 바뀐 동작 중 의도와 다른 것을 고른다

**그 항목에서 동작이 바뀌었을 때만 낸다.** 무엇이 바뀌었는지는 내가 알리고, 사용자는 **그중 의도와
다른 것**을 고른다. 바뀐 동작을 맞히는 자리가 아니다 — 정답이 없어 **채점하지 않는다.**
코드를 읽지 않고 답할 수 있어야 하므로 화면·데이터에서 보이는 말로 쓴다.

질문 문장은 고정이다 — 고정인 것은 뜻이고, 요청 언어가 한국어가 아니면 옮겨 쓴다(`response-language.md` 의 `## 고정 문장도 옮겨 쓴다`):

```
작업 항목 <N>. <이름> 으로 아래처럼 바뀌었습니다. 의도와 다른 것을 고르십시오.
```

- 보기는 **그 항목에서 바뀐 동작 2~4개** + 「전부 의도대로다」. `multiSelect`, `(추천)` 을 붙이지 않는다
- **보기는 이미 일어난 변화로 적는다** — `이제 ~하면 ~된다`. `~될까`·`어느 것이` 처럼 추측을 부르는
  꼴로 쓰면 맞히는 자리로 읽힌다
- **고른 보기 = 의도와 다른 변화다.** 아무것도 안 다르면 「전부 의도대로다」 하나만 고른다 —
  그 보기와 바뀐 동작을 함께 고르면 모순이라 알리고 다시 받는다
- 답을 받은 뒤 **「고르신 것 / 정답」 문형을 쓰지 않는다** — 고른 것을 받아 고칠 자리로 넘길 뿐이다
- **질문 문장에 작업 항목 번호와 이름을 적는다** — 무엇을 닫으며 묻는지가 질문만 보고 읽혀야 한다
- 코드·파일 이름·함수 이름을 보기에 쓰지 않는다. 그게 필요하면 코드 퀴즈 소재다
- **코드 퀴즈 인용이 함께 안 나가면 질문 본문에 그 항목 커밋들의 제목과 `요약` 란을 hash 와 같이 적는다**
  — hash 만으로는 무엇을 바꾼 커밋인지 안 보여 `git show` 를 따로 열어야 판단된다
  - 해당하는 항목 : 코드 퀴즈 소재가 없는 항목 · `--no-quiz` 로 코드 퀴즈가 꺼진 항목
  - `요약` 란이 없는 커밋 : 제목만 적는다 — 빈 란을 만들지 않는다
  - 인용이 함께 나가는 항목 : 적지 않는다 — 그 인용이 판단 자료다
- "의도와 다르다" 는 답이 나오면 **그 항목을 닫지 않고 같은 Step 의 다음 커밋으로 고친다** —
  체크박스는 고친 커밋의 `--done` 에서 켠다
- 그 항목에서 동작이 안 바뀌었으면(포맷·주석·이름변경·문서) 내지 않는다

## 한 호출에 담는다

작업 항목 경계의 멈춤은 **한 번**이고, 두 절이 **다음 Step 진행 여부·착수 전 질문과 같은
`AskUserQuestion` 호출에** 담긴다(`learning-protocol.md` 의 `## 사전문답은 전부 AskUserQuestion 으로 낸다`).
인용이 preview 를 넘어도 멈춤은 하나다 — 인용은 턴 끝 응답에 두고 알림으로 재개해
묻는다(§1 예측 퀴즈 `### 어디에 두나`).

| 닫은 항목 | 그 항목 몫으로 내는 것 |
|---|---|
| 소재 있음 + 동작 바뀜 | 코드 퀴즈 1 + 의도 재확인 1 (2문항) |
| 소재 있음 + 동작 그대로 | 코드 퀴즈 1 |
| 소재 없음 + 동작 바뀜 | 의도 재확인 1 |
| 소재 없음 + 동작 그대로 | 없음 — 다음 Step 질문만 남는다 |

- **도구 상한(한 호출 4문항)을 넘으면 같은 자리에서 창을 연달아 두 번 띄운다.** 문항을 빼서 맞추지 않는다

  | 창 | 담는 것 |
  |---|---|
  | 첫째 | 진행 여부 + 닫은 항목의 코드 퀴즈·의도 재확인 |
  | 둘째 | 다음 Step 의 착수 전 질문 — **첫째 창에서 진행을 골랐을 때만** |

  - 넘치지 않으면 한 창이다 — 나누는 것은 넘칠 때뿐이다
  - **Why:** 같은 자리에서 연달아 뜨는 창은 멈추는 시점이 하나다. 넘칠 때 코드 퀴즈를 빼면
    다음 Step 에 설계 선택이 붙은 흔한 경우(합계 5문항)마다 빠진다(#61 에서 사용자가 고름)
- 마지막 작업 항목이면 진행 여부 문항이 없다 — 닫은 항목 몫만 낸다
- `--no-ask` 면 **둘 다 내지 않는다.** 못 끄는 문항은 없다
- `--no-quiz` 면 **퀴즈를 내지 않는다** — 위 표를 「소재 없음」 줄로 읽는다. 동작이 바뀐 항목이면
  의도 재확인은 그대로 나간다
  - 끄는 것은 **맞히는 질문 셋** — 항목을 닫을 때의 코드 퀴즈와, 같은 창에 붙는 다음 Step 의 §1 예측 퀴즈·§5 이해 퀴즈다.
    §4 설계 선택은 고르는 질문이라 끄지 않는다(`learning-protocol.md` 의 `## 축은 둘이다`)
  - `--no-ask` 와 함께 오면 `--no-ask` 가 이긴다 — 전부 꺼진다
- 커밋 메시지에는 문답을 적지 않는다 — 무슨 변경이 있었는지 읽는 자리다. **문답은 대화에서 끝난다**

## 순회가 끝난 뒤 모아 묻는다 — `/wtflow:auto`

`/wtflow:auto` 순회 안에서는 작업 항목을 닫아도 멈추지 않는다. 각 커밋은 `--defer-ask` 로 질문을 미루고,
**마지막 Step 까지 커밋한 뒤 닫은 항목 전부의 질문을 한 자리에서 낸다.** 진행 여부 문항은 없다 — 순회가 이미 정했다.

| 절 | 순회 끝에서 내는 것 |
|---|---|
| §11 의도 재확인 | **동작이 바뀐 항목마다 한 문항** — 질문 문장에 작업 항목 번호·이름 |
| §7 코드 퀴즈 | **순회 전체에서 소재가 큰 것 1~2건만** — 고르지 않은 항목은 「소재 있음 · 안 냄」 한 줄 |

- **의도 재확인은 항목마다 다 낸다** — 그 항목에서 무엇이 바뀌었는지는 요건이라 빼면 완료를 확인할 근거가 없다
- **코드 퀴즈만 고른다** — 원래 「애매하면 안 내는 쪽」 인 문항이라, 항목 수만큼 늘리면 순회 끝 질문이
  항목 수의 두 배로 불어난다. 고르는 기준은 `### 소재를 거르는 기준` 의 왼쪽 열에 더 많이 걸리는 것
- **인용은 그 항목을 닫은 커밋 시점의 코드다** — 뒤 Step 이 같은 줄을 고쳤을 수 있다.
  `git show <닫은 커밋>:<파일>` 로 떠서 붙이고, 지금과 다르면 그 사실을 인용 머리에 적는다
- **도구 상한을 넘으면 같은 자리에서 창을 연달아 띄운다** — `## 한 호출에 담는다` 와 같은 규칙.
  창이 나뉘어도 한 항목의 문항은 한 창 안에 둔다
- **순서 : 판단 자료 → 질문 → 답 반영 → 브리핑.** 판단 자료(커밋 제목·`요약` 란·인용)는 턴 끝 응답으로 내고
  알림 재개로 묻는다(§1 예측 퀴즈 `### 어디에 두나`). 브리핑을 질문 앞에 두면 질문이 떠 있는 동안 요약돼 사라진다
- 「의도와 다르다」 가 나온 항목은 **체크박스를 그대로 두고 그 Step 에 고침 커밋을 더한다**
  (`/wtflow:commit --step <N>`) — 이미 닫힌 항목이라 끄지 않고, 고친 기록을 쌓는다
- `--no-ask` 면 순회 끝에서도 내지 않는다 · `--no-quiz` 면 코드 퀴즈를 뺀다

**Why:** 순회 중 항목을 닫을 때마다 멈추면 auto 를 부른 목적(사람이 Step 마다 끼어들지 않음)이 깨진다.
코드 퀴즈를 1~2건으로 줄인 것은 #61 에서 사용자가 고른 안이다 — 항목마다 다 내면 3항목에 6문항·창 2번이 된다.
