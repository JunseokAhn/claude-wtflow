# 응답 언어

사용자에게 내는 글을 어느 언어로 쓰는지. **모든 스킬이 시작 전에 읽는다.**

저장소 컨벤션이 덮지 않는다 — `convention-precedence.md` 의 대상이 아니다. 응답 언어는
저장소가 아니라 **그 자리에서 요청한 사람**에게 딸린 것이라, 팀 문서가 정할 수 없다.

## 대상

| 대상 | 대상 아님 |
|---|---|
| 자유 응답 문장 — 보고·요약·설명·멈춤 사유 | 커밋·이슈·MR 본문 — 저장소 관례를 따른다(각 컨벤션 문서) |
| `AskUserQuestion` 질문·보기 라벨·보기 설명 | 코드·식별자·명령·경로·에러 원문 — 원문 그대로 |
| 스킬이 정해 둔 고정 출력 블록(`✓ …`·`다음 단계 …`) | 브랜치 slug — 영어 kebab-case 규칙 그대로 |

## 요청마다 정한다 — 이 순서로

| 순서 | 근거 | 언제 쓰나 |
|---|---|---|
| 1 | **Claude Code `language` 설정** | 설정돼 있으면 언제나 — Claude Code 가 시스템 프롬프트로 이미 강제한다. 거스르지 않는다 |
| 2 | **이번 요청의 언어** | 설정이 없으면 기본 |
| 3 | **직전 대화 언어** | 이번 요청으로 언어를 알 수 없을 때 |
| 4 | **사용자 지시문(`~/.claude/CLAUDE.md`)의 언어** | 대화 첫 요청부터 언어를 알 수 없을 때만 |

- **세션 단위로 고정하지 않는다.** 한국어로 묻다가 영어로 물으면 그 요청부터 영어다
- **언어를 알 수 없는 요청** : `ok`·`ㅇㅇ` 같은 짧은 답 · `AskUserQuestion` 보기 선택 · 인자 없는 슬래시 명령
- **섞인 요청은 문장 뼈대의 언어로 본다** — `fix 브랜치 rebase 해줘` 는 한국어. 식별자·명령어는 세지 않는다
- **요청이 아닌 것은 근거가 아니다** — 붙여넣은 글·도구 출력·코드·스킬 문서의 언어로 응답 언어를 정하지 않는다

**Why:** 스킬 문서는 한국어, 도구 출력과 코드는 대개 영어다. 기준이 없으면 가장 최근에 읽은
텍스트의 언어로 쓰게 되어, 한국어로 묻는 사람에게 영어 보고가 나가고 한 화면에 두 언어가 섞였다.

## 한 응답 안에서 언어를 바꾸지 않는다

질문 문장·보기·그 뒤의 안내가 **같은 언어**여야 한다. 스킬 문서에 적힌 한국어 문장을 옮겨 쓰는
자리에서 가장 잘 섞인다 — 요청 언어가 한국어가 아니면 그 문장도 요청 언어로 옮겨 쓴다.

## 고정 문장도 옮겨 쓴다

스킬·참조 문서에 박힌 출력 블록(`✓ 이슈 생성 …`·`다음 단계 …`·`## 진행 현황 …`)과
질문 문장·`(추천)` 표기는 **한국어 원문 한 벌만 둔다.** 요청 언어가 한국어가 아니면 출력할 때
문장만 옮겨 쓴다.

| 그대로 두는 것 | 옮겨 쓰는 것 |
|---|---|
| 기호(`✓`·`▸`·`→`·`❓`)·명령·플래그·경로·`<자리표시자>`에 들어간 값 | 문장·표 머리글·상태 이름(`완료`·`진행 중`) |
| 줄 구성·줄 수·들여쓰기 — 명령과 설명이 한 줄에 서는 배치 | 보기 라벨의 `(추천)` → 그 언어의 같은 뜻 (`(Recommended)`) |

- **두 벌을 두지 않는 이유** — `language` 설정은 한국어·영어 밖의 언어도 받는다. 두 벌을 둬도
  그 밖의 언어는 옮겨 써야 하고, 고정 자리를 고칠 때마다 두 벌을 같이 고쳐야 한다
- 옮긴 문구가 실행마다 조금씩 달라지는 것은 감수한다 — 지켜야 하는 것은 뜻과 형식이다

## 어겼는지 보는 법

| 규칙 | 어겼는지 보는 법 |
|---|---|
| **요청 언어로 쓴다** | `language` 설정이 없고 요청 언어를 알 수 있는데 응답 문장의 언어가 다름 |
| **한 응답 한 언어** | 식별자·원문 인용을 뺀 문장 중 다른 언어 문장이 있음 |
