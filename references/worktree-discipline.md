# 워크트리 작업 규율

wtflow 스킬이 공유하는 규율. 브랜치 이름, K 모델, note 계층을 담는다.
**`plan`·`commit`·`auto`·`progress`·`merge` 가 시작 전에 읽는다.**

커밋 메시지 형식은 이 문서에 없다. `commit-convention.md` 를 본다.

## 워크트리 안에서의 행동 정책

- 작업하는 동안 워크트리 브랜치에서 떠나지 않음 — 다른 브랜치 체크아웃 금지
  (새 브랜치 생성 `git branch <name>` 은 OK)
  - **예외는 정리할 때뿐이다.** `wtflow-clean` 은 삭제 대상 브랜치를 워크트리가 물고 있으면
    기본 브랜치로 옮겨 체크아웃을 푼 뒤 지운다. 작업이 끝난 뒤라 지킬 작업물이 없다
- 큰 작업 임계: 4단계 이상 또는 1주 이상이면 통합 브랜치 + accumulator + 작업단위(K) 3단계 패턴.
  작은 작업은 기본 브랜치(`develop`, 없으면 `main`)로 직접 PR 1개로 충분

## 커밋 단위 = 태스크 / 분기(K) = 작업 항목

워크트리 작업은 2층이다:

- **작업 항목 = mirror 분기 K** — 작업 항목(주제)이 바뀔 때만 새 K.
- **태스크(작업 항목 내 하위 단위) = 커밋** — 진행하며 태스크마다 `/wtflow:commit` 으로
  같은 K 분기에 누적 커밋. ⚠️ 한 작업 항목의 여러 태스크를 커밋 없이 한 덩어리로 진행 금지(가장 흔한 실수).

**Why:** K 모델은 스킬에 있으나 '태스크마다 커밋' 규율이 약해 한 덩어리(batch)로 흐르던 것 보완.

### 멈추는 자리는 하나뿐 — 작업 항목 경계

**커밋 직전에는 묻지 않는다.** 구현과 검증이 끝나면 승인을 구하지 말고 곧장 커밋한다.
메시지는 커밋 컨벤션대로 짓고 결과만 보고한다.

**다음 작업 항목으로 넘어갈지만 사용자가 정한다.** 한 항목이 닫히면 거기서 멈춘다.
여러 항목을 사람 개입 없이 이어서 도는 것은 `/wtflow:auto` 를 사용자가 직접 불렀을 때뿐이다.

| | 묻나 |
|---|---|
| 커밋 직전 | ❌ 바로 커밋 |
| 같은 항목 안에서 태스크 추가 | ❌ 같은 K 에 누적 |
| 다음 작업 항목으로 전환 | ✅ 멈추고 확인 |

⚠️ 이 둘을 같이 없애면 여러 항목을 한 번에 밀어붙이게 된다. 그건 K 모델이 막으려던 문제다.

## 계획은 세션에, 공유 계약만 note 에

착수 전에 정한 상세(페이로드 계약·타입·에러코드·호출 순서)를 **이슈 본문에 밀어넣지 않는다.**
이슈는 "무엇/왜" + 큰 틀 작업 항목(=K)만.

**그 상세를 담는 곳은 세션이다.** `/wtflow:plan` 이 `EnterWorktree` 로 같은 세션을 워크트리에
밀어넣으므로 plan 출력이 그대로 살아 있고, 그 항목 순번이 곧 K 번호다. **파일로 다시 적지 않는다.**

**파일로 남기는 note 는 하나뿐이다:**

- `~/.claude/notes/<group>/_milestone/<iid>-<slug>.md` — 여러 이슈·레포가 공유하는 계약
  (`/wtflow:milestone`). 진행 중 고쳐지고 그 수정이 다른 브랜치·세션에서 즉시 읽힌다
  (단일 실체 + 심링크라서). **세션 하나가 대신 가질 수 없는 유일한 것**이라 파일로 남는다

`hooks/link-worktree-local.sh` 가 `<group>/` 를 워크트리의 `.claude/notes` 로 심링크하므로
워크트리 안에서는 `.claude/notes/_milestone/<iid>-<slug>.md` 로 경로가 항상 같다.

⚠️ **이슈는 note 를 참조하지 않는다 — `참고 자료` 섹션에도.** note 의 절 이름·로컬 경로·
K 번호 금지. 팀원에겐 그 파일이 없어서 깨진 포인터가 된다. 결합은 note 안에서만 표현하고,
이슈에 맥락이 필요하면 가리키지 말고 직접 풀어 쓴다.

⚠️ **진행 상태를 note 에 적지 않는다** — 체크박스·완료 칼럼·진행률 금지. **예외 없다.**
상태의 진실원은 이슈 체크박스와 mirror 분기이고, note 는 계약 저장소일 뿐이다. 둘로 갈리면
`wtflow:commit --done` 이 엉뚱한 항목을 체크한다.

### 이슈 없는 작업의 진행 상태 = mirror 분기

이슈가 없으면(`<prefix>/+<slug>`) 체크박스를 둘 곳이 없다. **K 귀속과 진행 상태를
mirror 분기(`<accumulator>-<KKK>`)로만 판정한다** — 뒤 3자리가 K 이고, 분기가 있으면 그 K 는
시작된 것, tip 이 그 K 의 최신 커밋이다. 항목 텍스트 자리는 그 커밋 제목이 대신한다.

따라서 `wtflow:commit --done` 은 **이슈 작업 전용**이다. 이슈 없는 작업에서는 켤 체크박스가 없다.

세션이 끊기면 항목 텍스트는 복구되지 않는다. K 번호와 커밋은 mirror 분기에 남으므로
`/wtflow:plan` 을 다시 불러 잔여 항목만 새로 세우면 된다.

**Why:** 계획 파일은 원래 "`issue` 실행 후 세션을 끄고 재진입하면 계획이 사라진다" 를 막으려
생겼다. `plan` 이 같은 세션을 워크트리로 옮기게 되면서 그 전제가 사라졌고, 남은 건 파일을 쓰고
갱신하는 비용뿐이었다. 세션이 대신 가질 수 없는 공유 계약만 파일로 남긴다.

## 브랜치 이름 규칙 (두 종류, 역할이 다르다)

| 종류 | 이름 (이슈 작업) | 이름 (이슈 없는 adhoc) | 누가 만드나 |
|------|------------------|------------------------|-------------|
| **워크트리 브랜치** (= accumulator = 작업 마커) | `<prefix>/#<N>-<slug>` | `<prefix>/+<slug>` | 자동 (plan) |
| **mirror 분기** (K별) | `<prefix>/#<N>-<slug>-<KKK>` | `<prefix>/+<slug>-<KKK>` | 자동 (commit) |

`#<N>` 자리에 `+` 하나가 들어간 것뿐이고 나머지 규칙은 전부 같다. `~`·`^` 는 git refname
금지문자라 마커로 못 쓴다.

- `<prefix>` 는 커밋 컨벤션과 같은 값(`fix`/`feat`/`refactor`/`docs`/`test`/`chore`) — 이슈 종류
  라벨에서 유도한다. **워크트리 브랜치에 `worktree/` 를 쓰지 않는다** — 브랜치 목록에서 이슈 종류가
  바로 읽히고, mirror 가 이름만 이어붙이면 되는 자연스러운 base 가 된다
- **워크트리 브랜치가 곧 이슈 마커다.** 별도 마커 브랜치를 따로 두지 않는다 — plan 이 만들고,
  워크트리에 체크아웃돼 있으니 커밋마다 자동 전진한다. 사용자가 미리 같은 이름으로 만들어 뒀으면
  새로 만들지 말고 **그대로 붙여 이어받는다**
- **mirror base = 워크트리 브랜치 이름 그대로.** 뒤에 `-<KKK>` 만 붙인다. 워크트리 밖에서 추론해야
  하면 기존 mirror(`git branch --list '*/#<N>-<slug>-[0-9][0-9][0-9]'`)에서 `-<KKK>` 를 떼면 된다
- `<KKK>` 는 3자리 zero-padding(`-001`) — `wtflow-clean`·`progress` 가 이 형태로 매칭한다.
  따라서 **accumulator 탐지 = `*/[#+]*` 중 `-[0-9][0-9][0-9]` 로 끝나지 않는 것**
- 워크트리 **경로**는 `.claude/worktrees/<N>-<slug>`(adhoc 은 `<slug>`) — `#`·`+` 를 넣지 않는다.
  브랜치명과 달리 경로는 셸에서 `#` 가 주석 시작이라, 따옴표가 빠지는 순간 조용히 잘린다

## 워크트리 진입은 wtflow:plan 경유

- 이슈 작업이면 `/wtflow:plan <N>` — `<prefix>/#<N>-<slug>` 브랜치를 붙인 워크트리를 만들고
  `EnterWorktree` 로 현재 세션을 인플레이스 이동시킨다 (새 세션 spawn 아님)
- **이슈가 없으면 `/wtflow:plan "<작업 설명>"`** — 이슈를 만들지 않고 질문으로 범위를 확정한 뒤
  `<prefix>/+<slug>` 워크트리로 진입한다. 그 뒤 auto·commit·progress 흐름은 이슈 작업과 동일
- **`claude --worktree` 금지** — 브랜치명을 제멋대로 지어서 컨벤션이 깨지고
  mirror 분기가 붙을 곳을 잃는다
- 부득이하게 `EnterWorktree` 를 직접 쓸 땐: `base_ref` 를 기본 브랜치(`develop`, 없으면 `main`)로
  명시 + `<prefix>/#<N>-<slug>` 를 `git worktree add <브랜치>` 로 먼저 붙인 뒤 그 경로로 진입
