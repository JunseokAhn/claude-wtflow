# plan — 재플랜

**워크트리 안 + 진행 이력이 있을 때만** 필요한 절(계약 2 의 넷째 행).
첫 plan 호출은 읽지 않는다.

계약·plan 출력 형식은 `skills/plan/SKILL.md`, adhoc 은 `plan-adhoc.md` 를 본다.

## 재플랜 모드 (워크트리 안 + 진행 이력 있음)

방향이 바뀌었거나 일부 완료된 뒤 다시 부를 때. **처음부터 다시 그리지 않고 현재 상태 기준 델타 플랜**을
낸다(기존 작업 롤백 안 함).

0. **계획 문서 로드** — 계약 6 과 동일(읽기만). 재플랜에서 특히 중요하다 — 컨텍스트가 압축돼도
   착수 전 계약이 note 에 남아 있다. **진행 상태를 여기서 읽지 않는다** — 상태는 1번에서만 온다
1. **진행 상태 수집**
   - **Step 진행 — mirror 분기가 기준**: `git branch --list '<accumulator>-[0-9][0-9][0-9]'`.
     번호=Step, tip=최신 커밋. **adhoc 은 이것이 유일한 소스다**
   - 체크박스 — **이슈 작업일 때만** (이슈 본문 조회 — `host-adapter.md` 의 `## 이슈 명령 대응`)
   - 세션 진행 — 대화 맥락상 완료된 작업 / 새로 생긴 방향. 세션이 끊겼던 adhoc 이면 항목 텍스트가
     없으므로 mirror tip 의 커밋 제목으로 대신 읽는다
2. **완료 접기** — 완료된 항목·Step 은 `✓` 한 줄 요약만
3. **스코프 드리프트 처리** (plan 표 **전에**) — 실제 작업이 작업 항목을 벗어났으면 되묻는다:
   (a) 이 브랜치에 **새 Step 으로 이어붙이기** / (b) **작업 항목에 추가**(이슈 작업이면 승인 후 이슈 본문
   수정, adhoc 이면 이번 plan 표에 추가) / (c) **별도 작업으로 분리**(`/wtflow:issue` 또는 새 adhoc
   워크트리). 추측 금지 — 선택에 따라 Step 번호·체크박스 동기화가 달라진다
4. **델타 plan 표** — 잔여 항목 + 신규 스코프만. 완료 Step 번호는 고정, 신규는 **`max(mirror KKK)+1`** 부터
   (mirror 는 이 브랜치에만 있어 타 작업 Step 오염 불가). 재사용·재배치 안 함
5. **출력 순서** — ① 완료 현황(✓) → ② (드리프트 시) 처리 선택 → ③ 델타 plan 표

재플랜은 **커밋·분기 안 함**(작업 항목 추가는 3-(b) 승인 시 이슈 본문에만). 저장할 파일이 없으므로
델타 plan 표를 낸 시점이 곧 종료다.
