# PR·MR 컨벤션

> **이 문서는 탐색 순서의 마지막 층(플러그인 기본값)이다.** 저장소 `.wtflow/` 나
> `~/.claude/wtflow/` 에 같은 이름의 파일이 있으면 그쪽 `##` 절이 이긴다 — `${CLAUDE_PLUGIN_ROOT}/references/convention-lookup.md`.

MR(GitLab)·PR(GitHub) 의 제목과 본문 형식. **`/wtflow:mr` 과 `/wtflow:briefing --mr` 이 읽는다.**

커밋 메시지 형식은 `commit-convention.md`, 이슈 형식은 `issue-convention.md`,
브랜치 이름·K 모델은 `worktree-discipline.md` 를 본다.

아래에서 **MR** 은 GitLab 의 merge request 와 GitHub 의 pull request 를 함께 가리킨다.

## 제목

**커밋 컨벤션의 `## Subject` 를 그대로 쓴다** — `<type>(<scope>): <한글 요약>`, 명사구 종결,
두 산출물이면 `+` 병기, 72자 이내. 여기 사본을 두지 않는다.

이슈가 있으면 **이슈 제목을 그대로 쓰는 것이 기본이다** — 같은 규칙으로 쓰였기 때문이다.

## 본문 — 저장소 MR 템플릿이 있으면 그것이 이긴다

이슈 본문이 저장소 이슈 템플릿을 따르는 것과 같은 규칙이다(`issue-convention.md` `## 본문 템플릿`).
리뷰어가 보는 문서라 팀 형식이 우선한다.

1. **템플릿 탐색 — 두 호스트를 다 본다** (Glob):
   - `.gitlab/merge_request_templates/*.md`
   - `.github/PULL_REQUEST_TEMPLATE.md` · `.github/PULL_REQUEST_TEMPLATE/*.md`

   둘 다 있으면 remote 호스트에 맞는 쪽, 호스트를 못 가리면 `.github/`.
   여러 개면 `Default.md` 우선, 없으면 사용자에게 묻는다
2. **헤더 고정** — 템플릿의 절 이름을 그대로 쓴다. **추가·삭제·개명 금지.**
   `<!-- ... -->` 작성 가이드 주석도 그대로 둔다
3. **아래 `## 기본 절 구성` 의 내용을 템플릿 절에 흡수시킨다** — 담을 절이 없다고 버리지 않고,
   **절을 새로 만들지도 않는다.** 가장 가까운 절에 한 줄로 넣는다
4. **`Closes #<N>` 같은 이슈 연결 줄이 템플릿에 있으면 채운다.** glab 의 `-i` 로 이슈를 엮더라도
   본문의 그 줄을 비워 두지 않는다 — 템플릿이 요구한 자리다
5. 템플릿이 없으면 아래 `## 기본 절 구성` 을 그대로 쓴다

## 기본 절 구성 (템플릿이 없을 때)

**헤더 6개 고정.** 문구·순서를 바꾸지 않고, **내용이 없어도 헤더를 지우지 않는다** — `없음` 한 줄을
적는다. 지우면 MR 마다 구성이 달라져 리뷰어가 매번 새 문서를 읽게 되고, 빈 칸이 "해당 없음" 인지
"안 적었음" 인지 구분되지 않는다.

```
## 무엇을 바꿨나
<커밋 1개 = 한 줄 (subject + 한 줄 효과) + 해시. 줄 수 = 커밋 수>

## 왜 이렇게
<이 diff 만 보면 안 드러나는 핵심 판단만 3줄 이내. 증상·원인 추적은 이슈로 링크>

## 호환성
<공개 API·이벤트 스키마·설정 키·마이그레이션에 생긴 변화. 없으면 "없음">

## 검증
<CI 가 안 돌리는 것 중 실제로 돌린 것. 없으면 "CI 파이프라인과 동일">

## 리뷰 포인트
<리뷰어가 실제로 봐야 하는 것 — 계획에 없다가 판단해 넣은 것, 운영 정책 결정, 조회할 수 없는 외부 상태. 없으면 "없음">

## 머지 주의
<배포 순서 의존·lockstep·롤백 플래그·데이터 영향. 없으면 "없음">
```

### 저장소 템플릿에 흡수시키는 예

4개 절짜리 템플릿(`요약` / `변경 사항` / `검증` / `참고 자료` + `Closes #`)이면 이렇게 넣는다:

| 기본 절 | 흡수 위치 |
|---|---|
| 무엇을 바꿨나 | `변경 사항` — 커밋 1개 = 한 줄 |
| 왜 이렇게 | `요약` — 왜 했는지 + 무엇을 했는지 |
| 검증 | `검증` — 실제로 돌린 것만 |
| 호환성 | `참고 자료` 에 한 줄. **변화가 있을 때만** — 없으면 줄을 만들지 않는다 |
| 리뷰 포인트 | `참고 자료` 에 한 줄. 있을 때만 |
| 머지 주의 | `참고 자료` 에 한 줄. 있을 때만 |

- **기본 절 구성과 달리 "없으면 `없음`" 을 쓰지 않는다** — 템플릿에 그 헤더가 없으므로 적을 자리도
  없다. 헤더가 있는 절만 `없음` 규칙을 따른다
- `Closes #<N>` 은 이슈 번호로 채운다

## 셀 수 있는 상한 (쓰고 나서 센다)

"간결하게" 는 검사할 수 없어서 지켜지지 않는다. 출력 직전에 **세어 보고 넘으면 다시 쓴다**:

| 대상 | 상한 |
|---|---|
| 커밋 나열 절(`## 무엇을 바꿨나` 또는 대응 절) | 커밋 수만큼의 줄 (커밋 2개면 2줄) |
| 판단을 적는 절(`## 왜 이렇게` 또는 대응 절) | 3줄 |
| 본문 전체 | 40줄 |

저장소 템플릿을 쓸 때도 이 상한은 그대로다 — 절 이름만 갈릴 뿐이다.

## UI 가 이미 보여주는 것을 적지 않는다

| 적지 않는 것 | 어디 있나 |
|---|---|
| 파일 목록·증감 수치(`+143/-13`)·`--stat` 표 | **Changes 탭** |
| 커밋 subject 나열·해시 목록 | **Commits 탭** |
| 테스트 통과 여부 중 CI 가 돌리는 것 | **Pipelines 탭** |

⚠️ 특히 **`영향 범위` 를 파일 표로 적지 않는다** — Changes 탭의 복사본이라 읽는 사람이 없다.
그 자리를 `## 호환성` 이 대신하는 이유가 이것이다: diff 를 봐도 안 드러나는 **의미상 영향**만 적는다.

## 덜어낸 근거는 버려지는 게 아니다

**MR 본문을 짧게 쓰라는 규칙이 지켜지지 않는 이유는 "이 근거를 버리기 아깝다" 이다.** 버려지지
않는다 — 이미 다른 데 있다. 요약해서 옮기지 말고 **가리킨다**:

| 무엇 | 어디에 이미 있다 |
|---|---|
| 증상·재현·원인 추적 | 이슈 본문 → `#N` 으로 링크 |
| 왜 그렇게 고쳤나의 상세·메커니즘 | 커밋 본문(`Why` 절) → 해시로 참조 |
| 계약·규격·미정 사항 | note (팀원에겐 없으므로 **MR 에서 가리키지 않는다** — 필요하면 풀어 쓴다) |

MR 본문은 **리뷰어가 판단하는 데 필요한 것만** 남긴다. 내가 어떻게 원인에 도달했는지는 그 대상이 아니다.
