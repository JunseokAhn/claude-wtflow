# note 형식

`~/.claude/notes/` 아래 두 note 의 규격. **`issue`(이슈 note)·`milestone`(마일스톤 note)이
쓰기 전에 읽는다.** `plan` 은 읽기만 하므로 이 문서가 필요 없다.

어느 note 가 있고 누가 언제 고치는지는 `worktree-discipline.md` 의
`## 상세는 이슈가 아니라 note 에` 가 정한다 — 여기는 **안에 무엇을 어떤 꼴로 적나**만 다룬다.

## 계약·설계 저장소이지 상태 저장소가 아니다

**두 note 에 공통으로 걸린다.** 진행 상태를 적는 순간 `wtflow:commit --done` 이 참조하는
이슈 체크박스와 어긋나 엉뚱한 항목이 체크된다.

| 정보 | 진실원 | note 에 적나 |
|---|---|---|
| Step 진행·완료·진행률 | 이슈 체크박스 + mirror 분기 `-00N` | ❌ |
| Step 번호·작업 항목·Step 제목 | 이슈 본문(이슈 없는 작업이면 mirror 분기) | ❌ 마일스톤 note 만 번호 참조 |
| 이슈 제목·open/closed | 호스트 | △ 대조용, 어긋나면 호스트가 이김 |
| 페이로드·타입·에러코드·호출 순서 | **note** | ✅ 본체 |
| 이슈 간 의존 순서 | **마일스톤 note** | ✅ 어느 호스트에도 없는 정보 |
| 여러 저장소가 한 마일스톤에 묶인다는 사실 | **마일스톤 note** (조직 레벨 없는 호스트) | ✅ `repos:` |

- 표에 담기는 건 **규격**이지 구현이 아니다 — 함수 본문·쿼리를 옮겨오지 않는다
- 근거 없는 칸은 행을 지어내지 말고 `(미정)`
- **두 note 사이에도 복사하지 않는다** — 원본이 바뀔 때 사본이 조용히 낡는다

## 이슈 note 형식

`~/.claude/notes/<group>/<repo>/issue-<N>.md`. `wtflow:issue` 계약 8 이 **한 번만** 만든다.
**착수 전 사고의 스냅샷**이지 유지되는 문서가 아니다 — 분량 제한 없이 규격을 못박는 게 목적:

```markdown
---
issue: <N>
repo: <group>/<repo>
created: 2026-08-18             # 상대날짜 금지 — 낡음을 판단하는 기준이 된다
---

## 배경          무슨 문제를 왜 푸는가 + 범위·전제 (2-4문장)

## 계약 요약      다른 사람·다른 레포가 맞춰 구현해야 하는 규격. 산문 말고 표로:
                엔드포인트 | 페이로드(필드·타입·필수·기본) | 에러코드 | 호환성·배포 순서

## 열린 질문      아직 안 정한 것 + 재검토 트리거 (있을 때만)
```

- **`branch:`·`milestone_note:` 는 넣지 않는다** — 브랜치 이름은 `plan` 이, 마일스톤은 이슈의
  배정이 각각 답한다. 여기 적으면 답이 둘이 된다

## 마일스톤 note 형식

`~/.claude/notes/<group>/_milestone/<식별자>-<slug>.md`.
**발행 문서가 아니라 마일스톤 내내 고쳐 쓰는 현행 계약**이라 분량 제한이 없다:

```markdown
---
milestone: <호스트에 등록된 제목 그대로>
host: github | gitlab | gitea
milestone_id: <글로벌 id>      # GitLab 전용, 이슈 배정용 (iid 아님). 다른 호스트는 생략
ref: <경로에 쓴 식별자>        # GitLab iid / GitHub number / Gitea id
group: <group path>
repos: [<repo>, …]            # 조직 레벨이 없는 호스트에서 같은 제목을 나눠 가진 저장소들
web_url: <마일스톤 URL>
---

## 목표·비범위    무엇을 왜 하는가 + 이번에 하지 않는 것 (경계가 이슈 분할을 결정한다)

## 공통 계약      여러 이슈·레포가 맞춰 구현해야 하는 규격. 산문 말고 표로:
                 엔드포인트 | 페이로드(필드·타입·필수·기본) | 에러코드 | 호출 순서 | 호환성

## 결정          따져서 고른 것만. 맥락 → 선택지 → 결정 → 트레이드오프 (한 줄씩)

## 위험과 대응    (해당될 때만) 위험 | 발생 조건 | 대응
                 데이터 형태 전환·배포 순서·하위호환처럼 위험이 곧 작업을 낳는 마일스톤에서만

## 이슈 분할      note 에도 호스트에도 없는 유일한 축
| 레포 | 이슈 | 제목 | 의존 |     (※ 상태 칼럼 없음)
```

- **이 문서가 계약의 유일한 원본이다.** 각 이슈의 `/wtflow:plan` 이 이 파일을 직접 읽는다 —
  어디에도 복사본이 없으므로 여기를 고치면 모든 이슈가 즉시 현행을 본다
- **`위험과 대응` 의 대응이 별도 작업이면 분할 표에 올린다.** 위험 검토가 새 이슈를 낳는 일이
  흔하다 — 마이그레이션 안전장치, 하위호환 가드, 롤백 경로 같은 것들이다. 위험만 적고 작업으로
  올리지 않으면 그 대응은 아무도 하지 않는다
